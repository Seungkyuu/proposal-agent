## 1. 고객사 리서치 요약

### [추진 동력]
iM라이프는 박경원 대표 취임 이후 **'리뉴얼(Renewal) iM라이프'**를 핵심 키워드로 설정하고, 중소형 보험사 한계를 극복하기 위한 전사 구조 개편을 진행 중이다.

- GA 중심 100% B2B 영업 모델 전환 완료
- 2026년 운영혁신본부 산하 **DAX(Digital & AI Transformation)팀 신설**
- K-ICS + IFRS17 대응 → 운영 자동화를 통한 비용 구조 개선이 DAX팀 신설의 핵심 비즈니스 논리

### [DAX팀 실제 구성] — v1.3 반영

| 구분 | 인원 | 기술 스택 | AI 도구 현황 |
|---|---|---|---|
| **개발직군** | 3명 | Java, JS, 이클립스 | Claude Code 주로 사용 중 (기사용) |
| **현업직군** | 3명 | 보험업무 전반 (상품·고객·운영) | AI 도구 경험 상대적으로 낮음 |
| **팀장** | 1명 | — | 금번 교육 제외 |

**핵심 교육 방향:** 개발자 위주 교육 아님 — **현업과 개발이 AI 도구로 함께 협업하는 체계 구축**
일반직원 대상 교육은 별도 편성 예정 (이번 과정 범위 외)

### [파일럿 대상 3종]
① 상품 IT 설계 ② 수수료 정산 ③ 수금 업무
→ 모두 현업(요구사항 정의)과 개발(구현·자동화) 경계에 걸친 업무

### [예상 허들]
1. **현업-개발 언어 장벽** — 개발자는 코드로, 현업은 업무 흐름으로 사고 → AI 도구를 공통 언어로 연결하는 것이 핵심
2. **보안 제약** — 보험 실데이터 외부 LLM 입력 불가 → 더미 데이터 3종으로 실습 맥락 확보
3. **개발직군 온보딩 수준 조정** — Claude Code 이미 사용 중 → 기초 설명 불필요, 현업 연동 심화로 바로 진입
4. **소규모(6명) 특성** — 강의식보다 워크숍·페어 실습 방식이 훨씬 효과적

## 2. 전략 포지셔닝

### 핵심 포지션
> **"개발자와 현업이 같은 도구로 같은 목표를 향해 달리는 DAX팀 협업 자동화 체계 구축"**
> Claude 생태계를 현업의 언어(자연어 지시)와 개발의 언어(Claude Code)가 만나는 접점으로 활용

### 3대 차별화 전략

| 차별점 | 내용 | iM라이프 DAX팀 연결고리 |
|---|---|---|
| **현업·개발 협업 중심 설계** | 동일 도구(Cowork)를 현업은 지시자로, 개발은 구현·검증자로 함께 사용하는 협업 워크플로우 체득 | 6명 소규모 팀 특성을 살린 페어 실습 구조 |
| **Claude Code 기사용자 심화 대응** | 기초 설명 생략, 현업 연동·Java/JS 스택 통합 시나리오 중심으로 즉시 심화 진입 | 개발직군 3명 Claude Code 기사용 사실 반영 |
| **보험 업무 특화 더미 데이터** | 수수료 정산·수금·상품 설계 더미 데이터 3종 사전 제작 — 실데이터 보안 제약 Zero 영향 | 파일럿 3종 즉시 전이 가능한 실습 구조 |

### 피치 스타일
- **스타일:** 실습/결과 중심 실전형 — 6인 소규모 워크숍
- **근거:** 6명이므로 강의식 아닌 페어 실습 + 강사 밀착 코칭이 효과 극대화

## 3. 교수설계 모델 선택

| 항목 | 내용 |
|---|---|
| **선택 모델** | **SAM 모델 (Successive Approximation Model — 애자일 교수설계)** |
| **선택 근거** | 빠른 프로토타입 → 반복 피드백 → 개선 루프가 현업-개발 협업 구조와 정확히 일치. 현업이 요구사항을 지시하고, 개발이 Claude Code로 구현하고, Cowork로 결과를 검토하는 흐름이 SAM의 반복 사이클과 동일 |
| **매핑 변수** | 목표 유형 O=2(협업 체계 구축·실습), 교육 기간 D=1(1일 8H), 인원 = 6명 소규모 |

## 4. 커리큘럼 — 8H 타임라인

**교육 대상:** iM라이프 DAX팀 6명 (개발 3 + 현업 3)
**교육장:** 알파코 성수 캠퍼스 | **계정:** 알파코 제공 Claude 유료 계정
**강사 구성:** 주강사 1인 (6명 소규모 — 보조 강사 불필요)
**도구 체계:** Claude Chat → Cowork → Claude Code 현업 연동 (공통 레이어 중심)
**최종 산출물:** 현업+개발 협업 자동화 워크플로우 1개 이상 (재사용·공유 가능 형태)

> **설계 원칙:**
> - 이론 45분 이내. 6명 소규모라 워크숍 밀도 최대화.
> - 현업(지시자)과 개발(구현자)이 같은 실습을 다른 역할로 수행 — 도구 하나가 두 역할 모두 수용.
> - 개발직군 Claude Code 기초 설명 생략 — 현업 연동 시나리오로 바로 심화 진입.
> - 보험 실데이터 외부 LLM 입력 불가 → 알파코 더미 데이터 전면 활용.

## 6. 도구 체계 — Claude 생태계 3레이어 (현업+개발 협업 매핑)

```
Layer 1 — Claude Chat (공통 자연어 인터페이스)
  └─ 현업: 프롬프트로 업무 지시 / 개발: 출력 검증·템플릿 구조화
  └─ 세션 2: DAX팀 공용 Project + 수수료 보고서 프롬프트

Layer 2 — Cowork (현업+개발 공통 파일 자동화 레이어)
  └─ 현업: 자연어 지시만으로 파일 처리 / 개발: 워크플로우 재사용성 확보
  └─ 세션 3: 수수료 CSV 집계 + 수금 미납 추출

Layer 3 — Claude Code (개발 중심, 현업 연동 구조로 심화)
  └─ 현업: 요구사항 자연어 정의 / 개발: Java/JS 스택 연동 스크립트 생성
  └─ 세션 4: 상품 설계 자동 정제 + DAX팀 CLAUDE.md

[파일럿 업무 매핑]
  수수료 정산 → Layer 1 + Layer 2 (현업 보고 + 자동 집계)
  수금 업무   → Layer 2 (미납 추출·현업 보고서)
  상품 IT 설계 → Layer 3 (현업 요구사항 → 개발 스크립트)
  페어 자유 실습 → 레이어 자유 선택 (세션 5)
```
