# 리서치 브리프 (Research Brief)
**고객사:** iM라이프 DAX팀 | **작성일:** 2026-06-16 | **버전:** v1.1 [수정됨]

---

## 1. 추진 동력 (Why Now)

박경원 대표 취임 이후 **'리뉴얼(Renewal) iM라이프'** 선언 — 중소형 보험사 한계 극복을 위한 전사 구조 개편 가속화.

- GA 중심 100% B2B 영업 모델 전환 완료
- 2026년 운영혁신본부 산하 **DAX(Digital & AI Transformation)팀 신설**
  - 구성: 개발직군 3명 + 현업 3명 = 총 6명 (팀장 제외)
  - 개발직군: Java/JS/이클립스 스택, Claude Code 기사용
  - 현업직군: 보험업무 전반(상품·고객·운영) 담당
- K-ICS + IFRS17 대응 → 운영 자동화로 비용 구조 개선이 DAX팀 신설의 핵심 비즈니스 논리

출처: The Bell 등 금융업계 보도 + 사용자 제공 팀 구성 정보

---

## 2. 실행 단계 (Current State)

**팀 신설 직후 — 현업+개발 협업 자동화 체계 구축이 최우선**

- 개발직군: Claude Code 이미 활용 중 → 기초 설명 불필요, 현업 연동·협업 방식 심화 필요
- 현업직군: AI 도구 경험 상대적으로 낮음 → Chat·Cowork 중심, 개발 결과물을 이해하고 활용하는 방법 필요
- 파일럿 3종: ① 상품 IT 설계 ② 수수료 정산 ③ 수금 — 모두 현업+개발 경계에 걸친 업무
- 일반직원 교육은 별도 편성 → 이번 과정은 DAX팀 내부 협업 체계 구축에 집중

---

## 3. 핵심 페인 포인트 (Pain Points)

1. **현업-개발 간 언어 장벽** — 개발자는 코드로 생각, 현업은 업무 흐름으로 생각 → AI 도구가 이 둘을 연결하는 공통 언어가 되어야 함
2. **보안 제약** — 보험 실데이터 외부 LLM 입력 불가 → 더미 데이터 기반 실습
3. **개발직군 심화 방향** — Claude Code를 이미 쓰지만 현업과 연동하는 협업 워크플로우는 미구축
4. **소규모(6명) 특성** — 강의식 아닌 워크숍·페어 실습 방식이 효과적

---

## 4. 전략 방향 (Strategy Direction)

> **"개발자와 현업이 같은 도구로 같은 목표를 향해 달리는 DAX팀 협업 자동화 체계 구축"**
> Claude 생태계를 현업의 언어(자연어 지시)와 개발의 언어(Claude Code)가 만나는 접점으로 활용한다.
