# Phase 1 - 기획안 (01_strategy.md)
> 고객사: 경기도청 | 작성일: 2026-06-25 | 공동 제안: SK AX
> 과정명(안): **경기도 현업 맞춤 AI Agent 제작 실무 과정**
> 대상: 경기도청 임직원 25명 / 초중급 / 24H = 6회차 × 4H, 주 1회 분산 / 오프라인(알파코)+온라인(SK AX)

## §1. 고객사 리서치 요약 (research_brief 기반)

- **추진 동력:** 경기도는 국내 최초 '인공지능 기본조례'(2024.7) 제정 후 '2026~2030 AI 종합계획'을 수립 중. 4대 방향 중 **'AI 행정서비스(혁신행정)'**가 본 과정과 직결. 도정 슬로건 "변화의 중심, 기회의 경기".
- **실행 단계:** **전국 지자체 최초 자체 생성형 AI 플랫폼(소버린 AI) 행정 도입(2025.11~).** 6대 기능(업무 지원관·문서 작성·행정자료 검색·회의 관리·행정심판·자치법규 입안). 검색 -50%·문서작성 -37%·요약 -30%, 5천여 명이 8천 건 이상 활용.
- **핵심 페인:** ①도구는 있으나 현업의 '직접 제작' 역량 부재 ②행정 문서·데이터의 업무 특화 활용 미흡 ③AI 결과 신뢰·검증·보안 판단력 부족.
- **결론:** 경기도는 'AI 도입' 단계를 통과했다. 다음 과제는 **현업이 자기 업무용 AI Agent를 직접 만드는 제작자 전환**이다.

## §2. 전략 포지셔닝

- **핵심 포지션(한 문장):** "경기도가 만든 AI 행정 인프라 위에서, 현업을 **'AI 도구 사용자'에서 '내 업무용 AI Agent 제작자'로 전환**하는 실전 과정."
- **3대 차별화 전략:**
  1. **인프라 위의 제작 역량** — 범용 도구 사용을 넘어, 바이브코딩으로 현업 맞춤 Agent를 직접 완성. 경기도 플랫폼 6대 기능과 1:1 정렬된 실습.
  2. **플랫폼이 못 하는 영역 정조준** — 단발 생성·요약·검색(플랫폼 영역)은 제외. 다단계·판단형(교차검증·민원 인사이트)으로 차별적 가치 창출.
  3. **신뢰·검증 + 확장성 내장** — 결과 검증·환각 방지 체크리스트를 산출물에 탑재하고, 재사용 템플릿화로 팀·조직 확산 경로까지 설계.
- **피치 스타일:** **LIGHT_AGILE** (현업 실무진 대상 — 이론 최소화, 실습·산출물 중심). 대상-스타일 정합 확인됨.
- **SK AX 연결고리:** 산출물(Agent) 완성·평가 설계가 SK AX 'AI Bootcamp' 인증 트랙과 정합. **직접 연계 표기 없이 연결 여지만 명시.**

## §3. 교수설계 모델

- **채택 모델: SAM(애자일 교수설계) + 최종 회차 PBL.**
- **선택 근거 (Skill 04 매핑):** 목표유형 O=3(현업 실전 적용), 기간 D=2(단기 분산), 평가 A=2(산출물 포트폴리오). 결정트리 Q4(최신 AI 툴 실습 위주) = YES → **SAM** 우선. 6회차마다 프로토타입을 빠르게 만들고 1주 간격으로 현업 적용 후 피드백을 반영하는 반복 구조.
- **주 1회 분산의 강점:** 회차 간 1주를 "현업 과제 적용 → 다음 회차 피드백" 사이클로 활용 → 연속 집합 대비 실무 전이(transfer) 극대화.
- **일관성 검증:** 최종 6차에 팀별 Agent 데모·산출물 심사(PBL 30%+) 배치 → 모델-커리큘럼 정합.

## §4. 커리큘럼 (5열, 6회차 × 4H, 주 1회)

과정 목표: **행정 업무 진단 → 바이브코딩 제작 → 현업 맞춤 AI Agent 완성**을 통한 현업 실무 자동화 역량 확보.

| 차시 | 세부 주제 | 핵심 내용 | 실습 도구 및 액티비티 | 최종 산출물 |
|------|---------|---------|-------------------|-----------|
| 1차 (4H) | AI Agent·바이브코딩 입문 + 업무 진단 | Agent 구조(입력-처리-**판단**-검증), 바이브코딩 개념, 교차검증 대상 업무 진단 | Claude.ai·Cursor 첫 실행, 업무 진단 워크숍 | 자동화 타깃 Top3 + Agent 흐름도 초안 |
| 2차 (4H) | 개발환경 + 프롬프트·컨텍스트 설계 | Claude Code/Cursor 셋업, 프롬프트·컨텍스트로 '판단 규칙' 설계 | 환경 셋업, 단일 서류 처리 미니 Agent | 개인 개발환경 + 첫 미니 Agent |
| 3차 (4H) | 다단계 워크플로우 설계 (교차검증 1차) | 신청서↔요건 대조 로직, 누락·불일치 판단 흐름 | 교차검증 Agent 1차 구현(규칙 기반 대조) | 교차검증 Agent v1 (핵심 anchor) |
| 4차 (4H) | 다출처 데이터·규정 연결 | 자격요건·구비서류 기준 연결(RAG/규칙), Open API 보강 | 기준 데이터 연동, data.go.kr API 결합 | 기준 연동형 교차검증 Agent v2 |
| 5차 (4H) | 고도화·신뢰검증 + 심화 분기 | 누락·불일치 정확도 향상, 환각 방지·근거 제시, 검증 체크리스트 / **[심화] 민원 인사이트·취합·모니터링 분기** | 검증 체크리스트 적용, 심화팀 파이프라인 구축 | 검증 내장 Agent v3 / 심화 Agent 초안 |
| 6차 (4H) | 완성·발표·팀 자산화 (PBL) | 팀별 완성본 데모, 산출물 심사, **재사용 템플릿화·확산** | 최종 빌드·디버깅, 데모 발표, 템플릿 분리 | 실행 가능 Agent 완성본 + 재사용 템플릿 + 발표자료 |

> 온/오프라인 배분: 개념·사전 영상은 온라인(SK AX, 약 20%), 제작 실습·피드백은 오프라인(알파코, 약 80%).
> 핵심 anchor(교차검증형)는 3~6차에 걸쳐 누적 완성 → **전원이 실행 가능한 완성본 1개 확보**. 역량 있는 팀은 5차에서 민원 인사이트·취합·모니터링형으로 분기.
> 정부24 직접 연동은 인증·보안 한계로 **데모/미래 시나리오**로 다루며, 실제 연동 실습은 공공데이터포털(data.go.kr) Open API로 대체.

## §4-A. 실습 체계 재설계 — 플랫폼이 못 하는 '다단계·판단형' Agent

> **설계 원칙:** 경기도 소버린 플랫폼이 이미 제공하는 **단발 기능(문서 생성·요약·검색·회의록)은 실습에서 제외**한다.
> 플랫폼이 못 하는 4가지에만 집중한다 — ①다단계 워크플로우 ②부서 고유 규칙·판단 내장 ③다출처 데이터 통합·교차검증 ④재사용 가능한 팀 자산화.
> 난이도 구성: **핵심 1개(교차검증형) 전원 완성 + 심화 선택**.

### ◆ 핵심 anchor (전원 완성) — 교차검증형 Agent
**"신청서 ↔ 자격요건·구비서류 자동 대조·검증 Agent"**
- **개념:** 보조금·지원사업 신청서(또는 인허가 서류)를 자격요건·제출서류 기준과 자동 대조하여 **누락·불일치·기한 초과를 플래그**. 단순 생성이 아닌 '규칙 기반 판단 + 근거 제시' 다단계 워크플로우.
- **실현가능성 ◎** 문서+규칙 조합으로 4H 내 완성, 비개발 현업도 바이브코딩으로 도달.
- **유용성 ◎** 수작업 대조의 오류·누락은 책임이 크고 반복적 — 즉시 체감되는 시간·리스크 절감.
- **확장성 ◎** 사업·서식만 교체하면 타 사업/타 부서로 템플릿 복제. 팀 표준 자산화 용이.
- **부서 적용 예:** 복지국(보조금 자격 대조), 미래성장산업국(지원사업 신청 검증), 도시주택실(인허가 구비서류 점검), 자치행정국(각종 신청 접수 검증).

### ◆ 대표 심화 (선택) — 민원 인사이트형 Agent
**"대량 민원 군집·근본원인 분석 → 정책 제언 Agent"**
- **개념:** 누적 민원 원문을 **군집·트렌드 분석**해 반복 민원의 **근본 원인과 정책 제언**을 도출. 단순 응답(플랫폼 영역)을 넘어 '분석→인사이트→제언'의 상위 가치.
- **실현가능성 ○** 텍스트 군집·요약 파이프라인, 4~8H 심화 트랙 적정.
- **유용성 ◎** 민원 대응을 '처리'에서 '정책 개선'으로 전환 — 의사결정자 어필 강함.
- **확장성 ◎** 민원 외 VOC·설문·콜로그 등 비정형 텍스트로 확장.
- **부서 적용 예:** 자치행정국(열린민원실), 기획조정실(정책기획), 사회혁신경제국.

### ◆ 보조 심화 선택지
| 유형 | 한 줄 정의 | 실현·유용·확장 | 부서 적용 예 |
|---|---|---|---|
| 취합·정합성형 | 시군·부서 제출자료 표준화·정합성 자동 점검·종합 | ○ / ◎ / ◎ | 기획조정실, 각 실국 총괄 |
| 데이터 모니터링형 | Open API+도 데이터 지표 추세·이상치 선제 알림 | ○ / ◎ / ◎ | 기후환경에너지국, 농수산생명과학국, 보건건강국 |

### ◆ 확장성(Scalability) 설계 — 1인 제작을 넘어서
- **팀 자산화:** 개인 Agent를 **재사용 템플릿(입력·규칙·검증 분리)**으로 구조화 → 부서 전체가 공유.
- **조직 확산:** 우수 산출물을 **AI국 연계**로 부서 표준 Agent 후보로 승격(직접 표기는 협의 후).
- **메타 역량(가장 확장적인 성과):** 수료 후 **새로운 Agent를 스스로 설계**하는 역량 체득 — 과정이 끝나도 자생적으로 자동화가 늘어나는 구조.

```
[전체 스토리 흐름]
Why    — 경기도는 지자체 최초 AI 플랫폼을 갖췄지만, 현업은 '사용자'에 머물러 자기 업무용 Agent를 직접 만들지 못한다.
What   — 6회차 종료 후, 각자 자기 업무를 자동화하는 '실행 가능한 AI Agent 완성본'을 손에 쥔다.
How    — 바이브코딩으로 진입장벽을 없애고, 행정 문서·규정·데이터로만 실습하며 1주 간격 현업 적용 사이클로 체득한다.
Result — 도구 사용자에서 제작자로 전환된 현업 인력이 부서로 확산하는 'AI 행정 자생력'이 조직에 남는다.

[회차별 아크 위치]
1차 — Why  : 내 업무를 진단해 교차검증 타깃을 스스로 찾으며 '왜 제작이 필요한가'를 체감
2차 — What : 첫 미니 Agent를 완성해 '무엇을 만들 수 있는가'를 손으로 확인
3차 — How  : 신청서↔요건 대조 다단계 워크플로우로 교차검증 Agent를 구현
4차 — How(심화) : 기준 데이터·Open API를 연결해 판단 근거를 확장
5차 — How(고도화) : 검증 내장으로 '신뢰할 수 있는 Agent' 완성 / 역량팀은 심화 분기
6차 — Result : 완성본 데모 + 재사용 템플릿화로 부서 확산의 출발점 확보
```

## §6. 차시별 핵심 논지 + 불릿 초안 (Phase 2 직접 원천)

```
[1차]
핵심 논지: 도구가 아니라 '내 업무'에서 출발해 자동화 타깃을 스스로 진단한다
주요 불릿:
  • 입력-처리-출력-검증 4단계로 AI Agent 구조를 분해
  • 바이브코딩으로 비개발 현업도 첫날 제작에 진입
  • 부서 업무 진단 워크숍으로 자동화 타깃 Top3 도출

[2차]
핵심 논지: 한 번 만든 개발환경이 6회차 내내 제작의 기반이 된다
주요 불릿:
  • Claude Code·Cursor 환경을 개인별로 직접 구축
  • 프롬프트·컨텍스트 설계로 결과 품질을 통제
  • 문서 요약 미니 Agent로 첫 완성 경험 확보

[3차]
핵심 논지: 단발 생성이 아니라 '대조해 판단하는' 다단계 Agent를 만든다
주요 불릿:
  • 신청서와 자격요건을 자동 대조하는 흐름 설계
  • 누락·불일치·기한 초과를 근거와 함께 플래그
  • 플랫폼이 못 하는 규칙 기반 판단을 직접 구현

[4차]
핵심 논지: 흩어진 기준과 데이터를 연결해 판단 근거를 넓힌다
주요 불릿:
  • 자격·서류 기준을 RAG·규칙으로 Agent에 연결
  • 공공데이터 Open API로 외부 근거를 보강
  • 사업·서식 교체만으로 타 업무에 복제 가능

[5차]
핵심 논지: 신뢰할 수 없는 결과는 행정에서 쓸 수 없다 — 검증을 내장한다
주요 불릿:
  • 누락·불일치 판단 정확도를 검증으로 끌어올림
  • 환각 방지·근거 제시를 산출물에 기본 탑재
  • 역량팀은 민원 인사이트·취합형으로 심화 분기

[6차]
```

- ⚠ **사용자 확인 요청:** 경기도 공식 CI HEX(경기 블루/그린)를 주시면 즉시 교체합니다.
- 폰트: 맑은 고딕 / 상단 30pt·헤더 18pt·불릿 14pt·표 11~12pt.
