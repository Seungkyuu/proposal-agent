## [00_requirements_definition_rules]
# Agent Skill 00: Requirements Definition & Pre-Flight (Phase 0)

## 0. 개요

**본 스킬은 파이프라인 최초 진입점이다.**
에이전트가 고객사명과 교육 주제를 입력받으면, 기획·디자인·렌더링 작업을 시작하기 전에 반드시 이 스킬을 먼저 실행한다.

**목적:**
사용자로부터 제안서 생성에 필요한 모든 정보를 구조화된 질문으로 수집하고, "요구사항 정의서"를 작성하여 사용자의 승인을 받는다. 승인 전까지 Phase 1(기획안)은 절대 시작하지 않는다.

**실행 순서:**
```
Skill 00 (Phase 0) → 사용자 승인 → Skill 01~07 (Phase 1~3) → 사용자 승인 → 렌더러 (Phase 4)
```

```

① 고객사 기본 정보
  1-1. 고객사명 / 업종 / 규모 (직원 수 또는 계열사 수)
  1-2. 교육 의사결정자 직급·성함 (공개 가능 범위 내)
  1-3. 최근 AI·DX 관련 공개 선언이나 전사 정책이 있다면 알려주세요.

② 교육 요구사항
  2-1. 교육 주제 및 과목 수 (예: AI 활용 3개 과목)
  2-2. 교육 대상: 직급, 인원 수, 현재 AI 활용 수준 (초급/중급/고급)
  2-3. 총 교육 시간 및 일정 (예: 총 24시간, 3일 집합)
  2-4. 교육 형태: 집합 / 온라인 / 혼합
  2-5. 교육장 인터넷 환경: 자유롭게 사용 가능 / 망분리로 외부 접속 불가 / 미확인
       (공공기관·금융기관은 반드시 확인 — 결과에 따라 실습 도구 전체가 바뀜)
  2-6. 실습 PC 환경: 수강생 개인 노트북 지참 / 기관 PC 제공 / 미정
  2-7. 고객사 주요 업무 목록
       (예: 어떤 공문서를 주로 작성하는지, 민원 유형, 보유 데이터 현황 등

③ 제안서 조건
  3-1. 제출 기한
  3-2. 단독 제안 여부 (경쟁 입찰인지 단독인지)
  3-3. 특별히 강조하고 싶은 포인트 (있다면)
  3-4. 절대 포함하면 안 되는 내용 (있다면)
  3-5. KPI·사후관리 납품 범위
       (교육 종료 후 실제로 제공 가능한 범위를 사전 확정
        예: 만족도 조사만 / 4주 리마인더 발송 / 6개월 ROI 추적
        → 확정된 범위만 제안서에 기재. 실행 불가능한 내용 기재 금지)

④ 알파코 자산 확인
  4-1. 이번 제안서에 활용 가능한 실제 레퍼런스 고객사명
       (공개 불가라면 업종+규모로 익명 처리 가능 여부)
  4-2. 별도 브랜드 컬러 가이드 또는 로고 파일 있으면 공유해 주세요.

⑤ 산출물 스펙
  5-1. 희망 슬라이드 분량 (예: 18~20장)
  5-2. 섹션 구분 슬라이드 포함 여부
  5-3. 견적·가격 슬라이드 포함 여부
  5-4. 교육 일정표 슬라이드 포함 여부
       ※ 알파코 회사 소개 슬라이드는 기존 제안서 소스 덱에서 항상 제공되므로 별도 확인 불필요.
          Phase 2 레이아웃 설계 시 자동 포함 처리.
```

# Agent Skill: Education Proposal Planner & Intent Capture Rules (V4. Asset-First Integrated)

## 0. [파이프라인 진입 전 필수] Phase 0 — Skill 00 참조

> **이 섹션은 `00_requirements_definition_rules.md`(Skill 00)로 완전히 이관되었다.**
> 에이전트가 고객사명을 최초로 입력받으면 Skill 00을 즉시 실행하여 요구사항 정의서를 작성하고 사용자 승인을 받는다. Skill 00 승인 완료 후에만 Section 2(고객사 리서치)로 진입한다.

---

## 1. 개요 (Overview)
본 사양은 에이전트가 파이프라인 시작 시([STATE: DISCOVERY]), Section 0 Pre-Flight Check 완료 후 사용자가 입력한 고객사명과 교육 주제를 바탕으로 '교육 주제 맞춤형 고객사 사전 리서치(Topic-Centric Pre-Search)'를 자동으로 실행하고, 이를 기반으로 고도로 구조화된 '교육제안 기획서(Proposal Planner)' 및 자가 진단 리포트를 수립하는 규칙을 정의한다.

---

## 2. 교육 주제 연동 자동 사전 리서치 규칙 (Pre-Search Query & Extraction)
사용자가 최초로 `[고객사명]`과 `[교육 주제]`를 입력하면, 에이전트는 질문을 던지기 전에 웹 검색 엔진(Web Search)을 가동하여 다음 3대 영역을 즉각 리서치해야 한다.

### ① 검색 쿼리 세트 자동 생성 및 실행 (Search Queries)
* 기본 비즈니스 행보 쿼리: `"{고객사명} {교육 주제} 도입"`, `"{고객사명} {교육 주제} 추진"`
* C-Level 메시지 및 비전 쿼리: `"{고객사명} 신년사 {교육 주제}"`, `"{고객사명} 대표 {교육 주제}"`
* 실무 조직 및 동향 쿼리: `"{고객사명} {교육 주제} 활용"`

### ② 핵심 인사이트 추출 (Insight Extraction)
검색된 뉴스 및 공식 문서 데이터에서 다음 3가지 핵심 팩트(Facts)를 추출하여 임시 컨텍스트 버퍼에 바인딩한다.

1. **[추진 동력]:** 고객사가 해당 주제(예: AI/AX)와 관련하여 최근 대외적으로 선포한 핵심 비전이나 전사 정책.
2. **[실행 단계]:** 자체 포털 구축, 외부 SaaS 도입, TF 조직 결성 등 현재 고객사가 도달한 기술적/실무적 실행 단계.
3. **[예상 허들]:** 망분리 보안 규제, 임직원의 디지털 격차, 실무 적용 유스케이스 부족 등 해당 기업이 겪고 있을 핵심 페인 포인트 추정치.

## 3. 리서치 기반 맞춤형 5대 역질문 프로토콜 (Tailored Questionnaire)
에이전트는 단순히 준비된 질문을 복사 붙여넣기 하지 않고, 앞서 자동 리서치된 인사이트를 질문 서두에 자연스럽게 녹여내어 전문성을 증명하며 질문해야 한다.

* ❌ **나쁜 질문 예시:** "수강생들의 직급과 AI 숙련도는 어떻게 되나요?"
* ⭕ **좋은 질문 예시 (리서치 연동형):**
  > "최근 S사가 전사 업무 효율화를 위해 '사내 자체 AI 포털'을 구축하고 업무 자동화를 가속화하고 있는 행보를 포착했습니다. 이번 교육을 듣는 대상 분들도 이 사내 포털이나 AI 도구를 현업에서 직접 활용해야 하는 실무진급 분들인가요? 그분들의 대략적인 현재 AI 숙련도 수준도 함께 알려주세요."

## 4. '교육제안 기획서' 표준 출력 서식 (Proposal Brief Template)
에이전트는 수집된 답변과 사전 리서치 데이터를 종합하여, 아래 구조의 명확한 '교육제안 기획서' 초안을 마크다운 형태로 렌더링한다.

```
# [교육제안 기획서] {고객사명} 대상 {교육과정명} 수립 안

## 1. 교육 개요 및 대상 정의
* **고객사명:** {고객사명}
* **희망 과정명 (추천):** {과정명}
* **교육 대상 및 규모:** {직무/직급}급 {인원수}명
* **현재 역량 레벨:** {초급 / 중급 / 고급}
* **교육 일정/기간:** 총 {N}일 (총 {H}시간)

## 2. 사전 리서치 및 제안 배경
* **고객사의 최신 행보 (★자동 분석):** {자동 사전 리서치로 파악된 해당 교육 주제 관련 기업의 최신 움직임 요약}
* **역량 Gap 및 Pain Point:** {고객사 행보 대비 임직원들이 겪는 실무상의 진짜 문제점}
* **교육 수립 방향:** {이 문제를 깔끔히 해결하기 위해 교육이 도달해야 할 최종 지향점}

## 3. 제안사 핵심 전략 매칭
* **제안사의 강점:** {선택된 제안사의 1순위 독보적 전문성}
```

## 6. 웹 검색 실패 시 Fallback 프로토콜 (Search Failure Fallback)

에이전트는 Section 2의 웹 검색이 실패하거나 결과가 불충분할 때, 아래 프로토콜을 순서대로 실행한다.

### Case 1: 검색 결과 0건 (Zero Results)
1. **1차 재시도:** 쿼리를 단순화하여 재검색 (`"{고객사명} AI"`, `"{고객사명} 디지털전환"`)
2. **2차 재시도:** 영문 쿼리로 전환 (`"{company_name} AI strategy"`, `"{company_name} digital transformation"`)
3. **수동 입력 요청 (Fallback):** 2회 재시도 모두 실패 시 사용자에게 아래 3항목 직접 입력 요청:
   - [추진 동력]: "현재 고객사의 AI/AX 관련 핵심 추진 방향이나 전사 정책을 알려주세요."
   - [실행 단계]: "현재 어느 단계에 있나요? (검토 중 / 파일럿 / 전사 도입 중)"
   - [예상 허들]: "가장 우려하는 현장 문제나 장벽이 무엇인가요?"
4. **최종 처리:** 사용자 입력값으로 기획서 진행. 리서치 출처 필드에 "사용자 직접 입력 (검색 불가)" 명시.

### Case 2: 검색 결과 관련성 낮음 (Low Relevance)
- 결과가 존재하지만 고객사 + 교육 주제와 직접 관련 없는 경우 (동명이인 기업, 전혀 다른 분야 뉴스 등)
- **조치:** 상위 3개 결과 관련성 판단 후 70% 미만이면 Case 1 Step 3으로 전환
- **부분 활용 허용:** 관련 있는 항목만 추출하고, 나머지는 "정보 부족 — 사용자 확인 필요"로 명시

### Case 3: 네트워크 에러 / API 타임아웃
- **자동 재시도:** 최대 2회, 지수 백오프 (5초 → 10초)
- **최종 실패 시:** 사용자에게 "⚠ 웹 검색 일시 불가 — 수동 입력 모드로 전환합니다" 안내 후 Case 1 Step 3으로 전환

## [03_design_deconstruction_reconstruction_rules]
# Agent Skill: Reverse Design Engineering & Template Deconstruction-Reconstruction (V4. Clean Setup)

## 1. 개요 (Overview)
본 사양은 에이전트가 사용자가 업로드한 레거시 제안서 파일(PPTX, PDF, 이미지 등)을 입력받았을 때, 해당 문서의 '비주얼 DNA(Visual DNA)'와 '기획적 스토리 톤(Story Tone)'을 완벽하게 역공학(Reverse Engineering)하여 분석하고, 새롭게 기획될 제안서에 일관되게 이식·재구성하기 위한 기술 제어 규칙을 정의한다. 강사진 프로필 레이아웃은 전면 배제한다.

---

## 2. 양식 역공학 3대 분석 레이어 (Deconstruction Layers)

에이전트는 제공받은 기존 문서를 다음 3가지 핵심 축으로 정밀 분석(Deconstruct)하여 메모리 컨텍스트에 바인딩한다.

```
[레거시 파일 입력 (PPTX / PDF)]
│
├── LAYER 1: 비주얼 스타일 파싱 (Visual Style Extraction)
│     - 도미넌트/서브/액센트 컬러 세트 추출
│     - 텍스트 정렬 기준(Left/Center), 마진(여백) 크기, 라인 데코레이션 양식 감지
│     - 슬라이드 내 레이아웃별 정보 밀도(Density - 여백 대비 텍스트 비율) 분석
│
├── LAYER 2: 스토리라인 전개 흐름 분석 (Document Flow Extraction)
│     - 제안 논리의 빌드업 흐름 감지 (두괄식 결과 우선형 vs 귀납적 문제제기형)
│     - 장표 간의 전환(Transition)을 위한 브릿지 간지(Section Divider) 사용 주기 확인
│
└── LAYER 3: 문장 톤앤매너 추출 (Tone & Voice Extraction)
      - 사용 단어의 전문성 수준(학술 용어 vs 직관적 실무 용어) 분석
      - 불릿 포인트 뒤의 문맥 구조 및 어미 패턴 (~ 기여, ~ 추진 vs ~를 통한 가치 극대화)
```

---

## 3. 톤앤매너 이식 및 새 슬라이드 재구성 규칙 (Reconstruction Rules)

추출된 DNA를 기반으로 새로운 요구사항에 맞춤형 제안서를 재구성할 때, 에이전트는 다음 규칙을 강제 적용한다.

### 규칙 1: 템플릿 슬라이드 레이아웃의 '의도' 계승
* 에이전트는 기존 문서의 장표를 분석하여 '레이아웃 매핑 테이블'을 생성한다.
* 새 제안서를 기획할 때 임의의 레이아웃을 생성하지 않고, 기존에 분석된 매핑 테이블 안에서 가장 기능적으로 어울리는 레이아웃 슬라이드를 원본에서 복사하여(Clone) 뼈대로 삼는다.
* *예: 기존 제안서의 특정 슬라이드가 표지, 실적 테이블, 3단 블록 나열 등의 레이아웃을 사용했다면 ➔ 새로운 제안서의 `[제안사 소개 및 실적 레퍼런스]` 장표를 생성할 때 해당 슬라이드의 오브젝트 좌표와 표 서식을 1:1 복제한 뒤 텍스트 내용만 덮어쓴다 (강사 이력 프로필 카드 레이아웃 복제 전면 금지 — 배제 기준 상세는 **Skill 01 Section 7** 참조).*

### 규칙 2: 비주얼 여백(Breathing Room)의 비율 보존
* 기존 문서의 디자인 퀄리티가 높은 핵심 이유는 '적절한 비움의 미학'에 있다.
* 에이전트는 원본 문서의 평균 글자 수(Character Count per Slide)를 측정하고, 새로운 슬라이드를 기획할 때 원본 글자 수의 ±15% 한계선을 넘지 않도록 텍스트 다이어트 가중치를 동적으로 조절한다.

### 규칙 3: 문장 밀도 및 어미의 인공적 결합 (Semantic Copycat)
* 원본이 개조식 위주의 컴팩트한 명사형 종결을 썼다면 새 제안서도 100% 명사형으로 일치시킨다.
* 원본이 '~을 통한 ~의 실현'과 같은 대구법(Parallelism) 구조를 반복했다면, 에이전트가 새로 생성하는 슬라이드의 불릿 포인트 헤더 역시 동일한 대구적 리듬감을 살려 카피라이팅을 수행한다.

# Agent Skill: Instructional Design Model Selection & Search Engine

## 1. 개요 (Overview)
본 사양은 에이전트가 Step 4(교육 설계) 단계를 수행할 때, 요구사항 분석 결과를 바탕으로 최적의 교수설계 모델(Instructional Design Model)을 알고리즘적으로 매핑하고 구체적인 커리큘럼 아키텍처로 변환하기 위한 기술적 규칙을 정의한다.

---

## 2. 탑재할 교수설계 모델 라이브러리 (Model Library)

에이전트는 아래 5가지 핵심 교수설계 모델의 정의, 목적, 적용 방식을 지식 베이스(Knowledge Base)에 내재화한다.

1. **역방향 설계 모델 (Backward Design)**
   * **철학:** "원하는 최종 비즈니스 결과(Outcome)를 정의하고, 이를 달성하기 위한 평가 기준을 먼저 세운 뒤, 커리큘럼을 역산하여 설계한다."
   * **적용 대상:** 생산성 지표 향상, 시간 절감 등 명확한 ROI 산출이 필요한 직무 교육.

2. **SAM 모델 (Successive Approximation Model - 애자일 교수설계)**
   * **철학:** "기획-설계-개발을 선형적으로 진행하지 않고, 프로토타입을 빠르게 만들어 반복 피드백을 수용하며 점진적으로 완성한다."
   * **적용 대상:** 기술 변화 속도가 빨라 즉각적인 툴 실습과 반복적 결과물 피드백이 중요한 AX/IT 실무 교육.

3. **PBL 모델 (Problem-Based Learning - 문제 해결형 학습)**
   * **철학:** "실제 현업의 미해결 과제(Problem)를 제시하고, 학습자가 주도적으로 해결책을 도출하는 프로젝트 중심 학습."
   * **적용 대상:** 팀장급 이상의 전략 수립 과정, 해커톤, 사내 과제 해결형 액션 러닝(Action Learning).

4. **ADDIE 모델 (전통적 체계적 교수설계)**
   * **철학:** "분석(A) -> 설계(D) -> 개발(D) -> 구현(I) -> 평가(E)의 5단계 정석 파이프라인에 입각해 빈틈없는 교육 프레임워크를 수립한다."
   * **적용 대상:** 전사 임직원 대상 공통 역량 교육, 신입사원 입문 교육, 장기 로드맵 교육.

5. **Gagne(가네)의 9가지 교수사태 (9 Events of Instruction)**
   * **철학:** "주의 집중부터 일반화까지 인간의 내적 학습 과정을 자극하는 9가지 수업 사태를 설계하여 단기 학습 몰입도를 극대화한다."
   * **적용 대상:** 단기 특강(1일 2~4시간), 핵심 개념 전달 위주의 세미나성 교육.

## 3. 교수설계 모델 자동 매핑 알고리즘 (Selection Logic)

에이전트는 임의로 모델을 선택하지 않고, 고객의 인풋 데이터로부터 매핑 점수 M을 계산하여 가장 점수가 높은 모델을 선정한다.

### [의사결정 변수 정의]
* **목표 유형 (O ∈ {1, 2, 3, 4}):**
  - 1: 마인드셋/개념 학습, 2: 도구 숙달/실습, 3: 현업 실전 적용, 4: 비즈니스 문제 해결
* **교육 기간 (D ∈ {1, 2, 3}):**
  - 1: 초단기 (1일, 8시간 이하), 2: 단기 (2~5일), 3: 중장기 (1주일 이상)
* **평가 엄격도 (A ∈ {1, 2, 3}):**
  - 1: 단순 만족도 조사, 2: 과제/포트폴리오 평가, 3: 비즈니스 ROI 산출 (비용/시간 절감량)

### [수학적 매핑 모델 (Mapping Score Formula)]
각 교수설계 모델 k에 대한 매핑 적합도 점수 M_k는 다음과 같이 정의된다.

```
M_k = w1 * O_k(O) + w2 * D_k(D) + w3 * A_k(A)
```

이때 가중치: w1 = 0.5, w2 = 0.25, w3 = 0.25
에이전트는 max(M_k)를 만족하는 교수설계 모델 k를 최종 채택한다.

### [실무형 단순 판단 매핑 트리 (Decision Tree Fallback)]
수식 연산 이후, 직관적 검증을 위해 아래 매핑 규칙을 크로스 체크한다.

* **Q1. 교육 목적이 구체적인 업무 성과(시간/비용 절감)인가?** ➔ YES ➔ **[역방향 설계 모델]** 우선 검토
* **Q2. 교육 기간이 1일(8시간) 이하의 특강성 교육인가?** ➔ YES ➔ **[가네의 9가지 교수사태]** 우선 검토
* **Q3. 교육 형태가 '해커톤' 또는 '사내 과제 해결' 중심인가?** ➔ YES ➔ **[PBL 모델]** 우선 검토
* **Q4. 교육 대상이 최신 개발/AI 툴 실습 위주인가?** ➔ YES ➔ **[SAM 모델]** 우선 검토
* **그 외 일반적인 전사 역량 교육인가?** ➔ YES ➔ **[ADDIE 모델]** 적용

만약 에이전트가 "바이오 제약 연구원을 위한 AI 가속화 과정"과 같이 생소한 도메인 교육 요구사항을 수신했을 때, 에이전트는 자체 지식을 활용하여 다음과 같이 커리큘럼 소스를 수집하고 검증한다.

## 2. 커리큘럼 설계의 5단계 레이아웃 매트릭스 (Curriculum Matrix)

에이전트가 생성하는 모든 커리큘럼 모듈은 단순한 주제 나열이 아닌, 반드시 아래 5대 필수 요소(Matrix)가 상호 연동된 구조로 명세화되어야 한다.

| 차시 (Time/Session) | 세부 주제 (Topic) | 핵심 학습 내용 (Core Concept) | 실습 및 액티비티 (Hands-on/Tool) | 최종 실습 산출물 (Artifact) |
| :---: | :--- | :--- | :--- | :--- |
| **시간/일차** | 구체적인 핵심 학습 타이틀 | 다루는 핵심 개념 및 이론 | 실제 탑재할 실습 환경 및 프롬프트 템플릿, AI 도구 | 수강생이 이 세션을 마쳤을 때 손에 쥐는 실물 결과물 |

* **❌ 가짜 실습 예시:** "AI 프롬프트 실습 진행" (산출물이 명확하지 않음)
* **⭕ 진짜 실습 예시:** "Claude Code 연동 실무 자동화 툴 빌드 실습" ➔ [산출물: 사내 DB 연동형 FAQ 자동 생성 챗봇 프로토타입]

```json
  "top_message": "현업 즉시 적용 가능한\n{고객사명} 맞춤형 {N}일 커리큘럼",
  "content": {
    "table_data": {
```

## 3. 대상(Target Audience)별 커리큘럼 튜닝 규칙 (Audience Tuning)

에이전트는 Step 1(기획서 작성)에서 확보된 교육 대상의 속성에 따라 실습 도구와 이론 비율, 최종 결과물의 성격을 완벽하게 다이어트해야 한다.

# Agent Skill: Curriculum Benchmarking & Validation Rules

## 1. 개요 (Overview)
본 사양은 에이전트가 설계한 커리큘럼의 시장 정합성 및 학술적 공신력을 확보하기 위해, 실시간 웹 탐색(Web Search)을 통해 글로벌 우수 대학(MIT, Stanford, 서울대 등) 및 대표 에듀테크 플랫폼(Coursera, edX)의 유사 과정을 벤치마킹하고 검증(Validation)하는 기술적 규칙을 정의한다.

---

## 2. 벤치마킹 데이터 수집 파이프라인 (Data Sourcing)

에이전트는 Step 5(제안 커리큘럼) 도중 또는 직후, 다음 3가지 경로를 통해 실시간으로 벤치마크 대상 커리큘럼(Syllabus)을 수집해야 한다.

```
[커리큘럼 초안 생성 완료]
│
├── 1단계: 글로벌 우수 대학(Academic Class) 실러버스 서칭
│     - 검색 쿼리: "{주제} syllabus MIT", "{주제} course Stanford", "서울대 {주제} 강의 계획서"
│
├── 2단계: 글로벌 에듀테크 플랫폼(Industry Class) 벤치마킹
│     - 검색 쿼리: "{주제} Coursera professional certificate", "{주제} edX program"
│
└── 3단계: 시장 경쟁사 및 자격 인증 과정(Professional Class) 매칭
      - 검색 쿼리: "{주제} 국비지원 우수 훈련과정", "Microsoft/AWS {주제} official training"
```

---

## 3. 커리큘럼 정합성 검증 알고리즘 (Validation Algorithm)

에이전트는 수집한 외부 벤치마크 커리큘럼들의 핵심 키워드 집합 C_bench와 에이전트가 자체 생성한 커리큘럼 초안의 키워드 집합 C_gen을 비교하여 '정합성 얼라인먼트 점수(Alignment Score, AS)'를 계산한다.

### [수학적 검증 모델]
자체 생성한 커리큘럼이 글로벌 표준 대비 얼마나 필수 주제를 누락 없이 반영했는지에 대한 일치율(AS)은 다음과 같이 계산한다.

```
AS = |C_gen ∩ C_bench| / |C_bench| × 100 (%)
```

* **AS ≥ 85%:** '검증 완료(Verified)'. 바로 최종 제안서 커리큘럼으로 확정한다.
* **AS < 85%:** '보완 필요(Gap Detected)'. Section 3-1의 Gap 보완 알고리즘을 즉시 실행한다.

### 3-1. Gap 보완 상세 알고리즘 (Gap Refinement Logic)

AS < 85% 감지 시 에이전트는 아래 3단계 자동 보완 루프를 구동한다.

#### Step 1: Gap 키워드 추출
- C_bench(외부 기준) - C_gen(자체 초안)의 차집합 계산
- 예: `["RAG 패턴", "보안 망분리 대응", "API 연동 설계"]` 누락 감지

#### Step 2: 누락 모듈 자동 삽입 (Skill 05 커리큘럼 행렬 연동)
- 누락 키워드 기반으로 Skill 05의 CURRICULUM_TABLE에 신규 세션 추가
- **총 교육 시간 유지 원칙:** 기존 차시를 시간 분할하여 삽입, 원래 핵심은 압축 버전으로 유지
  - 예: "3차시 (2h) → 3a차시(1h: 기존 핵심) + 3b차시(1h: 신규 RAG 패턴 실습)"
- 추가된 세션은 Skill 05의 5열 고정 포맷을 준수하여 JSON에 반영

#### Step 3: 재검증 및 사용자 알림
- 보완 후 신규 AS 재계산
- **AS ≥ 85% 달성:** Phase 2 통과. 사용자에게 "Gap 보완 완료 (AS: {이전}% → {신규}%)" 알림
- **AS < 85% 여전히 미달:** 사용자에게 3가지 선택지 제시:
  * **옵션 A:** 교육 일수 확장 (예: 2일 → 3일) → 전파 규칙 Skill 10 Section 2 Variable 2 발동
  * **옵션 B:** 비핵심 토픽 제거 후 AS 재산정
  * **옵션 C:** 현재 AS로 진행 (리스크 인수 — 제안서 내 면책 문구 자동 삽입)

## 4. 벤치마킹 결과 활용 규칙

> **⚠️ 핵심 원칙: 벤치마킹 AS 검증은 내부 커리큘럼 품질 관리 도구다. 고객사 제안서 슬라이드로 출력하지 않는다.**

### 내부 활용 (허용)
- AS 점수는 Skill 09 Phase 1 Integrity Pass Audit 보고서에 기재하여 에이전트 자가 검증 용도로만 사용
- AS < 85% 시 커리큘럼 자동 보완 후 재검증 (Section 3-1 실행)
- 검증 결과는 Phase 1 GATE 보고서에 `[CV: PASS/FAIL] 벤치마킹 AS ≥ 85%` 형식으로 표기

### 제안서 슬라이드 출력 (금지)
- `COMPARISON_BENCHMARK` layout_type을 고객사 제안서 슬라이드로 생성하지 않는다.
- "커리큘럼 정합성 88%" 같은 수치를 고객사에게 직접 제시하지 않는다.
- 이유: 벤치마킹 수치는 내부 검증 지표이며, 고객사 의사결정 근거 자료로 적합하지 않다.

## 5. 실무 적용을 위한 프롬프트 가이드라인 (Prompt Guidelines)

1. **출처 명시 규칙 (Attribution Rule):**
   * 제안서에 단순히 "검증되었습니다"라고 쓰지 않는다. 구체적인 대학명, 플랫폼명, 혹은 최신 보고서(예: Gartner, McKinsey 2026 하이프 사이클)의 타이틀을 반드시 텍스트로 명시하여 신뢰도를 배가시킨다.

2. **최신성 필터링 (Recency Filter):**
   * IT/AX/DX 도메인의 경우 최소 최근 1년 이내에 개설되거나 개정된 커리큘럼만 수집 필터에 걸러지도록 검색 범위를 제한한다. (예: 3년 전의 구형 기술 스택 교육과정은 벤치마크 대상에서 자동 탈락시킴)

## 5-1. 웹 검색 실패 시 Fallback 프로토콜 (Benchmarking Search Failure Fallback)

Section 2의 벤치마킹 데이터 수집 검색이 실패할 경우 아래 순서로 처리한다.

1. **대체 쿼리 시도:** 플랫폼명 대신 주제 중심 쿼리로 전환
   - `"{주제} best practices 2025"`, `"{주제} enterprise training framework"`
2. **내부 지식 기반 대체 (Claude Knowledge Fallback):**
   - Claude의 학습 데이터 내 유사 커리큘럼 구조를 활용하여 C_bench를 추정 구성
   - **필수 명시:** 벤치마크 슬라이드 `top_message`에 `"★ 내부 지식 기반 추정 — 온라인 검증 권장"` 문구 삽입
3. **AS 기준 하향 조정 (Degraded Mode):**
   - 검색 불가 상황에서는 AS 기준을 85% → 75%로 하향 적용
   - Skill 09 Phase 2 Audit 보고서에 사유 자동 기재: `"[DEGRADED] 벤치마킹 검색 실패로 AS 기준 75% 적용"`
4. **사용자 알림:** "벤치마킹 검색에 실패하여 내부 지식 기반으로 대체 진행합니다. 결과물 검토 후 수동 보완을 권장합니다."

## [07_b2b_proposal_copywriting_rules]
# Agent Skill: B2B Proposal Copywriting & Headline Hooking Rules

## 1. 개요 (Overview)
본 사양은 에이전트가 제안서 내의 모든 헤드라인, 메인 메시지, 세부 본문 텍스트를 작성할 때, 평이하고 지루한 정보 전달식 문장 구조를 배제하고 고객사 의사결정권자(C-Level)의 심리를 자극하여 설득력을 극대화하는 'B2B 영업 특화 카피라이팅 기술'을 강제 적용하기 위한 규칙을 정의한다.

---

## 2. B2B 카피라이팅 3대 핵심 원칙 (Copywriting Pillars)

### 원칙 1: 행동 중심적 가치 제안 (Benefit-Driven Writing)
* 에이전트는 제품/교육의 '기능(Feature)'을 설명하는 데 그치지 않고, 그것이 고객사에게 가져다줄 '실질적 혜택(Benefit)'과 비즈니스 임팩트로 치환하여 서술해야 한다.
* ❌ **기능 나열형:** "Claude 3.5 Sonnet의 프롬프트 작성 기술을 교육합니다."
* ⭕ **혜택 중심형:** "LLM 프롬프팅 최적화를 통한 **사내 보고서 초안 작성 시간 80% 단축** 실현"

### 원칙 2: 교육 목표의 학술적 엄격성 (Bloom's Taxonomy)
* 커리큘럼 세부 내용 기술 시, 교육학의 '블룸(Bloom)의 교육목표 분류학'에 의거한 인지적 동사를 활용하여 명사형 종결을 수행한다. 단순 '이해', '학습'과 같은 모호한 동사는 일절 금지한다.
* **사용 금지 모호한 어휘:** `이해`, `파악`, `학습`, `교육`, `습득`
* **적극 권장 행동형 어휘:** `도출`, `구축`, `설계`, `자동화`, `비교·분석`, `마스터`, `실현`, `가속화`

### 원칙 3: 메인 메시지의 두괄식 구조 (Headline Hooking)
* 슬라이드 최상단 메시지 영역(30pt)은 전체 슬라이드의 결론을 압축하는 곳이다. 에이전트는 이곳에 단순 요약이 아닌, '수치(Numeric Indicator)'와 '행동 지향적 어휘'가 결합된 강력한 훅(Hook)을 배치해야 한다.
* **예시 구조:** `[고객사 당면 과제 해결]을 위한 [핵심 솔루션 키워드] 도입 및 [정량적 기대 효과] 달성`

---

## 3. 밋밋한 문장 ➔ 고품격 설득형 문장 변환 사전 (Conversion Table)

에이전트는 기획안 초안 작성 시 발생한 일반 서술형 문장을 감지하면, 백엔드 전송 전에 반드시 아래 규칙에 따라 '수주용 카피라이팅'으로 문장을 자가 보정(Self-Correction)한다.

| ❌ 일반적인 AI 생성 문장 (Passive/Informative) | ⭕ 카피라이팅 필터 적용 후 (Active/Persuasive) |
| :--- | :--- |
| 저희 교육은 실습 위주로 구성되어 있어 실무에 바로 적용할 수 있습니다. | **100% 실전 워크숍 형태** 구성, 현업 복귀 즉시 **개인 맞춤형 솔루션** 작동 보장 |
| AI 기술의 발전 속도에 맞춰 인재들의 역량을 강화해야 합니다. | **경쟁사와의 격차를 해소**할 골든타임, **사내 AX 핵심 인재 조기 확보** 필수성 |
| 강의와 토론, 실습이 조화롭게 섞여 있어 지루하지 않습니다. | **[이론 30% : 실습 70%]** 비율의 완벽한 결합을 통한 **몰입형 러닝 저니(Learning Journey)** 설계 |
| 예산 대비 효율적인 과정을 기획했습니다. | **교육 품질 극대화**를 통한 **기업 실질 가치 200% 창출** 달성 |

---

## 4. 슬라이드 위계별 카피라이팅 분량 및 스타일 가이드

* **장표 메인 타이틀 (30pt):**
  - 최대 30자 이내. 무조건 1줄 구성을 원칙으로 하되, 25자가 넘어가면 세만틱 줄바꿈(`\n`) 적용.
  - 반드시 '강조하고자 하는 숫자'나 '고객사 이름'을 1개 이상 포함.

* **소제목 / 카드 헤더 (18pt):**
  - 명사형으로 완전히 컴팩트하게 압축 (8자 ~ 12자 내외).
  - *예: "01. 혁신 기반 다지기" ➔ "01. AI 체질 개선", "02. 실질적 역량 확보" ➔ "02. 실전 에이전트 빌드"*

* **본문 세부 불릿 (14pt):**
  - "~를 통한 ~ 달성", "~ 기반의 ~ 자동화" 등 앞뒤 대구가 맞아떨어지는 리드미컬한 2행 문장 구조 선호.

## [08_proposal_structure_and_operations_spec]
# Agent Skill 08: B2B 제안서 슬라이드 구조 명세 (V6. 18~20슬라이드 표준)

## 1. 개요

본 사양은 B2B 교육 제안서의 표준 슬라이드 구성과 각 슬라이드별 콘텐츠 명세를 정의한다.
슬라이드 수는 기본 18장이며, Skill 00 요구사항 정의서의 산출물 스펙에 따라 최대 20장까지 확장된다.

**알파코 회사 소개 슬라이드는 기존 소스 덱에서 항상 제공되므로 별도 기획 없이 자동 포함된다.**

---

## 2. 표준 슬라이드 구성 (18장 기본)

```
[표지]                                          ← 항상 포함
[목차]                                          ← 항상 포함

── Section 1: 제안 배경 ──
  S1-1. 제안 배경 및 필요성

── Section 2: 알파코 소개 ──
  S2-1. 알파코 회사 소개                        ← 소스 덱에서 자동 제공
  S2-2. 수행 실적

── Section 3: 교육 설계 ──
  S3-1. 교수설계 철학
  S3-2. 교육 목표 및 과목 개요
  S3-3. 커리큘럼 상세표

── Section 4: 알파코 강점 ──
  S4-1. 3대 독보적 강점 (USP)

── Section 5: 운영 계획 ──
  S5-1. 교육 운영 일정
  S5-2. KPI 및 사후관리
  S5-3. 견적                                    ← Skill 00 5-3 포함 여부에 따라 결정

[클로징]                                        ← 항상 포함
```

**섹션 구분 슬라이드(SECTION_DIVIDER) 5개 + 콘텐츠 슬라이드 11개 + 표지·목차·클로징 3개 = 기본 18장**
견적 포함 시 19장, 추가 커리큘럼 슬라이드 필요 시 20장.

---

## 3. 슬라이드별 콘텐츠 명세

### 표지 (TITLE_SLIDE)
- 고객사명 + 교육과정명 핵심 헤드라인
- 교육 대상·인원·총 시간 요약
- 제안사명(알파코), 제안 연월
- layout_type: `TITLE_SLIDE`

### 목차 (TABLE_OF_CONTENTS)
- Section 1~5 제목 나열
- layout_type: `TABLE_OF_CONTENTS`

### 섹션 구분 슬라이드 × 5 (SECTION_DIVIDER)
- 해당 섹션 번호 + 제목
- layout_type: `SECTION_DIVIDER`

### S1-1. 제안 배경 및 필요성
- 좌측: 현재 고객사의 구조적 한계 (As-Is) — Skill 01 리서치 기반
- 우측: 교육 후 전환 성과 (To-Be)
- layout_type: `PROBLEM_VS_SOLUTION`

### S2-1. 알파코 회사 소개 (COMPANY_INTRO)
- 소스 덱에서 자동 제공. 별도 콘텐츠 기획 불필요.
- layout_type: `COMPANY_INTRO`

### S2-2. 수행 실적 (VENDOR_PROFILE)
- Skill 00 4-1에서 확정된 레퍼런스 고객사명 기반 작성
- 공개 가능 고객사명 사용, 불가 시 업종+규모 익명 처리
- 익명 가상 데이터("서울시 투자기관 A") 사용 절대 금지
- 표 구성: 프로젝트명 | 고객사 | 과정 내용 | 기간 | 인원 | 만족도
- layout_type: `VENDOR_PROFILE`

### S3-1. 교수설계 철학 (FLOW_CHART)
- Skill 04에서 선택된 교수설계 모델 기반 3~4단계 흐름
- layout_type: `FLOW_CHART`

### S3-2. 교육 목표 및 과목 개요 (N_COLUMN_CARDS)
- 과목 수에 맞는 카드 구성 (2~4개)
- 각 카드: 과목명 + 핵심 역량 + 대표 산출물
- layout_type: `N_COLUMN_CARDS`

### S3-3. 커리큘럼 상세표 (CURRICULUM_TABLE)
- Skill 05 5열 고정 헤더: 차시 | 세부 주제 | 핵심 학습 내용 | 실습 도구 및 액티비티 | 최종 산출물
- Skill 00 2-5 인터넷 환경에 따른 실습 도구 적용 (Skill 05 §4-1 기준)
- layout_type: `CURRICULUM_TABLE`

### S4-1. 3대 독보적 강점 (N_COLUMN_CARDS)
- 알파코만의 USP 3개 카드
- 각 카드: 강점 제목 + 구체적 근거 + 고객사 연관성
- 가상의 강점 기재 금지 — 실제 제공 가능한 내용만
- layout_type: `N_COLUMN_CARDS`

### S5-1. 교육 운영 일정 (SCHEDULE)
- 월별 또는 주차별 교육 일정 타임라인
- 사전 준비 → 교육 실시 → 사후 관리 3단계 구조
- layout_type: `SCHEDULE`

### S5-2. KPI 및 사후관리 (EVALUATION_METRIC)
- **Skill 00 3-5에서 확정된 납품 범위 내에서만 기재**
- 기본 제공: Level 1 반응 평가 (만족도 조사)
- 선택 제공: Level 2~4는 사전 계약 확정 항목만 포함
- 실행 불가능한 평가 지표 기재 절대 금지
- layout_type: `EVALUATION_METRIC`

### S5-3. 견적 (PRICING) — 선택
- Skill 00 5-3에서 포함으로 확정된 경우에만 생성
- 과목별 단가 + 총액 구조
- layout_type: `PRICING`

### 클로징 (CLOSING_SLIDE)
- 마치는 인사 + 담당자 연락처
- layout_type: `CLOSING_SLIDE`

# Agent Skill 09: Pipeline Orchestration & Integrity Pass Rules (V11)

## 1. 개요

본 사양은 B2B 교육 제안서 생성 파이프라인의 전체 실행 순서, 단계별 사용자 승인 게이트(GATE), 자가 검증 루프를 정의한다.

**핵심 원칙:**
- 각 GATE에서 사용자의 명시적 승인 없이는 다음 단계로 진행하지 않는다.
- 각 Phase 내에서 자가 검증을 반드시 실행하고 결과를 사용자에게 공개한다.
- FAIL 항목이 있으면 자가 수정 후 재검증하고, 3회 이후에도 FAIL이면 사용자에게 수동 확인을 요청한다.

## 3. 동적 전파 알고리즘 및 복구 로직 (Propagation Protocol)

사용자가 특정 단계의 수정 데이터를 확정하는 즉시, 에이전트는 무조건 아래의 '체인 이펙트(Chain Effect)' 프로세스를 무대 뒤(Background)에서 구동시킨다.

### [체인 이펙트 실행 과정]
1. **수정 감지 (Diff Detection):**
   * 수정 전 데이터 D_old와 수정 후 데이터 D_new의 차이점을 파싱하여 영향도가 높은 핵심 키워드(예: "개발자" ➔ "임원진")를 식별한다.

2. **영향도 평가 (Impact Assessment):**
   * 의존성 그래프에 따라 재설계가 필요한 파이프라인 단계를 'Dirty' 상태로 마킹한다.

3. **순차적 자가 수정 (Cascade Refactoring):**
   * 마킹된 전·후방 단계들을 차례로 호출하여 컨텍스트를 동기화한다.
   * *예시 시나리오:* 사용자가 5단계 커리큘럼에서 "실전 데이터 연동 및 AI 코딩 구현"을 대규모로 추가하는 수정을 단행했을 때:
     - **역전파(Step 4):** 이론 위주의 기본 교수설계에서 **SAM(애자일 프로토타입) 및 PBL 모델**로 매핑 가중치를 자동 재계산하고, 제안서 내 교육 설계 철학 서술을 실습 지향형으로 자동 수정.
     - **순전파(Step 7):** 단순 1단계 반응 만족도 평가 중심에서 **2단계(학습 성취도 산출물 평가) 중심**으로 평가 계획 지표를 자동 승격.

## 4. 정합성 검증 지표 및 예외 경고 (Coherence Metric)

에이전트는 최종 PPTX 렌더링 데이터(JSON) 패키징 전, 제안서 내에 논리적 모순이 존재하는지 아래 2대 모순 필터로 전수 검사한다.

1. **대상-난이도 불일치 검사 (Audience-Level Clash):**
   * **진단:** 대상 수강생 수준이 '비전공자/초급'인데 커리큘럼에 'Python 코딩', 'AI 에이전트 직접 코딩 구축' 등 무거운 실무가 포함되어 있는가?
   * **조치 유형: 경고 + 자동 수정**
     - 사용자 승인 없이 커리큘럼을 "핵심 개념 데모 + 활용 시나리오 체험" 형태로 자동 경량화
     - 기획서 하단에 `[에이전트 자동 조정]` 주석 첨부: "초급 대상에 맞춰 코딩 실습을 데모 시연으로 전환하였습니다. 원래 내용을 유지하려면 수동 수정하세요."

2. **대상-피치 스타일 정합성 진단 (Audience-Pitch Mismatch):**
   * **진단:** 교육 대상이 '현업 실무진/개발자'인데 `pitch_style`이 `HEAVY_ACADEMIC`으로 설정되었는가?
   * **조치 유형: 경고만 (자동 수정 안 함)**
     - 사용자에게 경고 출력: "현업 실무진 대상이므로 `LIGHT_AGILE` 스타일을 권장합니다. 현재 설정을 유지하시겠습니까?"
     - 사용자 확인 없이 pitch_style을 변경하지 않음 (피치 스타일은 전략적 결정이므로 사용자 권한 보장)

3. **신규: 도메인-커리큘럼 미연동 감지 (Domain-Curriculum Misalignment):**
   * **진단:** 고객사 도메인이 "금융/보험"으로 명시되었으나 커리큘럼 내 실습 시나리오에 Skill 05 Section 4의 금융 도메인 키워드(여신 심사, 약관, 리포트)가 0건인가?
   * **조치 유형: 자동 수정**
     - Skill 05 Section 4의 해당 도메인 시나리오 템플릿을 CURRICULUM_TABLE rows에 자동 삽입
     - 삽입 후 Skill 06 AS 재검증 실행

# Agent Skill: Brain-to-Renderer JSON Data Contract Spec (V4. 9-Slide Aligned)

## 1. 개요 (Overview)
본 사양은 에이전트의 기획 모듈(Claude)이 기획을 마치고 생성한 데이터를 백엔드 자동화 엔진(Python-pptx)으로 안전하게 전달하기 위해 양자 간의 엄격한 데이터 필드 규격(Data Contract)을 정의한다. 이를 통해 사소한 키값 불일치 및 스키마 유효성 위반으로 인한 빌드 에러를 원천 예방한다.

## 2. JSON 스키마 메타 사양 (Meta Schema Constraints)

1. **엄격한 데이터 타입 매칭:**
   - 숫자는 반드시 `Integer` 또는 `Float` 타입이어야 한다.

2. **Null 값 방지 (No Undefined Rules):**
   - 기획안에 특정 항목 정보가 없다면, 빈 문자열(`""`) 혹은 빈 배열(`[]`)을 반환해야 하며, 필드 자체를 생략(Key Omission)하거나 `null` 값을 넘겨서는 안 된다.

## [13_source_deck_slot_mapping_rules]
# Agent Skill 13: 소스 덱 Slot Spec 매핑 규칙 (V1)

본 문서는 마스터 덱(alpaco_master.pptx)의 각 슬라이드에서 텍스트/테이블 요소를 교체할 때
shape 인덱스 기반 Slot Spec을 사용하는 규칙을 정의한다.

---

## 1. 개요

### 1-1. Slot Spec이란?
- PPTX 슬라이드 내 shape은 XML 순서가 디자인 변경 시마다 달라질 수 있다.
- Slot Spec은 각 layout_type별로 "어느 shape_idx에 어떤 콘텐츠를 주입할지"를 사전 정의한 JSON이다.
- 렌더러는 Slot Spec을 참조하여 위치 기반이 아닌 역할 기반으로 텍스트를 교체한다.

### 1-2. 파일 위치
```
templates/
└── master/
    ├── alpaco_master.pptx        # 레이아웃별 최적 슬라이드 취합본
    ├── slide_index.json          # layout_type → 마스터 슬라이드 번호
    └── slot_specs/               # layout_type별 Slot Spec JSON
        ├── TITLE_SLIDE.json
        ├── TABLE_OF_CONTENTS.json
        ├── SECTION_DIVIDER.json
        ├── COMPANY_INTRO.json
        ├── VENDOR_PROFILE.json
        ├── PROBLEM_VS_SOLUTION.json
        ├── FLOW_CHART.json
        ├── N_COLUMN_CARDS.json
        ├── CURRICULUM_TABLE.json
        ├── SCHEDULE.json
        ├── EVALUATION_METRIC.json
        ├── PRICING.json
        └── CLOSING_SLIDE.json
```

---

## 2. Slot Spec JSON 포맷

```json
{
  "template_id": "TITLE_SLIDE",
  "source_file": "(알파코)AIDP_KB국민은행_디지털금융실무 전문가과정 최종제안서.pptx",
  "source_slide_idx": 0,
  "master_slide_idx": 0,
  "slots": [
    {
      "slot_id": "top_message",
      "shape_idx": 1,
      "role": "main_title",
      "max_chars": 60,
      "max_lines": 3,
      "allow_newline": true
    },
    {
      "slot_id": "subtitle",
      "shape_idx": 2,
      "role": "subtitle",
      "max_chars": 40,
      "max_lines": 1,
      "allow_newline": false
    },
    {
      "slot_id": "meta_info",
      "shape_idx": 3,
      "role": "bullets",
      "max_chars_per_line": 40,
      "max_lines": 4,
      "allow_newline": true
    }
  ],
  "table_slots": [],
  "clear_after_shape_idx": 4,
  "notes": "우측 수직 포인트 바 shape은 건드리지 않는다"
}
```

### 필드 정의

| 필드 | 타입 | 설명 |
|---|---|---|
| `template_id` | string | layout_type과 동일 |
| `source_file` | string | 소스 덱 파일명 |
| `source_slide_idx` | integer | 소스 덱 내 0-based 슬라이드 인덱스 |
| `master_slide_idx` | integer | alpaco_master.pptx 내 0-based 인덱스 |
| `slots` | array | 텍스트 shape 교체 규칙 목록 |
| `slots[].slot_id` | string | 콘텐츠 필드명 (content 객체의 키와 매핑) |
| `slots[].shape_idx` | integer | 슬라이드 내 shape 순서 (0-based) |
| `slots[].role` | string | main_title / subtitle / bullets / card_header / card_body |
| `slots[].max_chars` | integer | 초과 시 폰트 축소 또는 줄바꿈 처리 |
| `slots[].allow_newline` | boolean | \\n 삽입 허용 여부 |
| `table_slots` | array | 테이블 교체 규칙 (아래 별도 정의) |
| `clear_after_shape_idx` | integer | 이 인덱스 이후 shape은 텍스트를 빈 문자열로 초기화 |

## 3. 테이블 Slot 포맷

```json
"table_slots": [
  {
    "slot_id": "table_data",
    "shape_idx": 5,
    "header_row": true,
    "header_style": "accent_color_bg_white_text",
    "body_row_style": "alternating",
    "col_widths_ratio": [0.1, 0.25, 0.3, 0.2, 0.15]
```

| 필드 | 설명 |
|---|---|
| `header_row` | true면 첫 행을 헤더로 처리 (배경색·굵기 적용) |
| `header_style` | accent_color_bg_white_text / dark_bg_white_text |
| `body_row_style` | alternating (홀짝 배경 교차) / flat (단색) |
| `col_widths_ratio` | 열 너비 비율 (합계 1.0) — CURRICULUM_TABLE은 [0.12, 0.18, 0.28, 0.22, 0.20] 고정 |

## 5. 렌더러 Slot 교체 알고리즘

```
slide_spec = proposal_json["slides"][i]
layout     = slide_spec["layout_type"]
spec_file  = f"templates/master/slot_specs/{layout}.json"
slot_spec  = load_json(spec_file)
master_idx = slot_spec["master_slide_idx"]

cloned = clone_slide(master_prs, master_idx, output_prs)

# 텍스트 슬롯 교체
for slot in slot_spec["slots"]:
    shape   = cloned.shapes[slot["shape_idx"]]
    content = resolve_content(slide_spec["content"], slot["slot_id"])
    replace_text(shape, content, slot)

# 테이블 슬롯 교체
for tslot in slot_spec["table_slots"]:
    shape      = cloned.shapes[tslot["shape_idx"]]
    table_data = slide_spec["content"]["table_data"]
    replace_table(shape, table_data, tslot)

# clear_after_shape_idx 이후 shape 초기화
for idx in range(slot_spec["clear_after_shape_idx"], len(cloned.shapes)):
    if cloned.shapes[idx].has_text_frame:
        clear_text(cloned.shapes[idx])
```

## 6. COMPANY_INTRO 특별 처리

- `COMPANY_INTRO` 슬라이드는 소스 덱의 알파코 회사 소개를 그대로 복제한다.
- **콘텐츠 교체 없음** — slot_spec의 slots와 table_slots가 빈 배열이어야 한다.
- `clear_after_shape_idx: 9999` (초기화 대상 없음)

---

## 7. Slot Spec 생성 절차

Slot Spec JSON은 수동으로 작성한다 (자동 생성 불가 — shape 역할 판단은 사람이 한다).

1. `python scripts/compile_master.py --inspect LAYOUT_TYPE` 실행
   → shape 인덱스별 현재 텍스트 미리보기 출력
2. 출력된 텍스트를 보고 각 shape_idx에 slot_id 부여
3. `templates/master/slot_specs/LAYOUT_TYPE.json` 작성
4. `python renderer/pptx_builder.py --test LAYOUT_TYPE` 로 샘플 슬라이드 검증

---

## 8. 에러 처리 규칙

| 상황 | 처리 |
|---|---|
| shape_idx가 슬라이드 shape 수를 초과 | 해당 슬롯 skip, 경고 로그 출력 |
| 텍스트가 max_chars 초과 | 글자 크기 자동 축소 (최소 8pt) |
| 테이블 행 수가 슬라이드 테이블 행 수 초과 | 마지막 행 스타일로 행 추가 |
| Slot Spec 파일 없음 | 렌더링 중단 + "Slot Spec 미생성" 에러 메시지 |

## [14_renderer_quality_rules]
# Agent Skill 14: 렌더러 품질 검증 규칙 (V1)

본 문서는 pptx_builder.py가 PPTX를 생성한 직후 수행하는 자가 품질 검증(RV) 체크리스트와
에러 처리 원칙을 정의한다.

---

## 1. 렌더러 품질 검증 항목 (RV Checklist)

Phase 4 완료 시 아래 항목을 순서대로 검증하고 결과를 콘솔에 출력한다.

### [RV-01] 슬라이드 수 일치
- **기준:** 생성된 PPTX의 슬라이드 수 == proposal_json["slides"]의 배열 길이
- **FAIL 조치:** 렌더링 중단 + "슬라이드 수 불일치: JSON {N}장 / PPTX {M}장" 출력

### [RV-02] 타 고객사명 미포함 (VENDOR_PROFILE 제외)
- **기준:** `extract-text`로 추출한 텍스트에서 `target_client` 외 다른 고객사명이
  VENDOR_PROFILE 슬라이드가 아닌 곳에 등장하지 않음
- **FAIL 조치:** 해당 슬라이드 번호와 발견된 텍스트 스니펫을 출력, 수동 확인 요청
- **검사 방법:** JSON metadata.client_name을 target_client로 등록 후 전체 텍스트 스캔

### [RV-03] 빈 텍스트 박스 없음 (콘텐츠 슬라이드 기준)
- **기준:** SECTION_DIVIDER, COMPANY_INTRO, CLOSING_SLIDE를 제외한 슬라이드에서
  주요 슬롯(top_message, 카드 헤더 등)이 빈 문자열이 아님
- **FAIL 조치:** "슬라이드 {N}: top_message 비어 있음" 출력 + 해당 슬라이드 번호 목록 반환

### [RV-04] 테이블 행 수 JSON과 일치
- **기준:** VENDOR_PROFILE, CURRICULUM_TABLE, PRICING 등 table_data가 있는 슬라이드에서
  실제 PPTX 테이블 행 수 == JSON rows 배열 길이 + 헤더 행(1)
- **FAIL 조치:** 테이블 행 재삽입 1회 자동 재시도 → 재시도 후 FAIL이면 수동 확인 요청

### [RV-05] 강사 관련 텍스트 최종 스캔
- **기준:** 생성된 PPTX 전체 텍스트에 아래 키워드 0건
  - `강사`, `이름`, `약력`, `경력`, `프로필`, `전문강사`, `강의 이력`, `학력`
- **FAIL 조치:** 발견된 슬라이드 번호 + 텍스트 스니펫 출력 후 렌더링 중단

### [RV-06] top_message 줄바꿈 검증
- **기준:** top_message 길이가 25자 초과인 경우 `\n`이 포함되어 있어야 함
- **FAIL 조치:** 자동으로 25자 기준 `\n` 삽입 후 재적용

### [RV-07] layout_type enum 유효성
- **기준:** 생성된 각 슬라이드의 layout_type이 Skill 08 §4 허용 목록 내 값이어야 함
- **FAIL 조치:** 해당 슬라이드 skip + "알 수 없는 layout_type: {X}" 경고 출력

## 4. Slot Spec 미생성 시 폴백(Fallback) 처리

Slot Spec JSON이 없는 layout_type은 아래 폴백 규칙을 따른다.

1. **경고 출력:** "Slot Spec 미생성: {layout_type}. 위치 기반 폴백 모드 사용."
2. **폴백 동작:** 슬라이드 내 텍스트 프레임을 보유한 shape을 순서대로 스캔
   - shape[0]: top_message
   - shape[1]: content.bullets[0..N] (줄바꿈으로 연결)
   - 테이블 shape: table_data.headers + rows 순서대로 주입
3. **폴백 결과는 RV-03(빈 텍스트 박스)을 WARN 수준으로 처리**
   (FAIL이 아닌 WARN — Slot Spec 생성 후 재렌더링 권장)
