# Agent Skill: Education Proposal Planner & Intent Capture Rules (V4. Asset-First Integrated)

## 0. [파이프라인 진입 전 필수] 제안사 자산 Pre-Flight Check

> **이 섹션은 Section 2(고객사 리서치) 이전에 반드시 실행해야 한다.**
> 에이전트가 고객사명과 교육 주제를 최초로 입력받으면, 웹 리서치를 시작하기 전에 아래 3가지를 먼저 확인한다. 이를 통해 제안사의 기존 브랜드 자산을 반영하지 않은 채 임의 디자인으로 제안서를 생성하는 오류를 방지한다.

### Pre-Flight 3개 질문 (순서 고정)

```
에이전트 발화 예시:
"[고객사명] 제안서 작업을 시작하기 전에 먼저 세 가지를 확인하겠습니다.

①  알파코의 기존 PPTX 제안서 양식 파일이 있으신가요?
    있다면 지금 업로드해 주세요. 그 양식을 그대로 살리면서 내용만 채워드립니다.

②  알파코 브랜드 컬러 가이드(로고 색상 등)가 별도로 있으신가요?

③  참고하고 싶은 이전 제안서(레퍼런스 덱)가 있으신가요?
    있다면 함께 업로드해 주시면 스토리 구조를 분석해서 이식합니다.

없으신 항목은 '없음'이라고 답해 주시면 바로 리서치를 시작하겠습니다."
```

### Pre-Flight 분기 처리

| 답변 | 에이전트 처리 |
|---|---|
| PPTX 양식 파일 업로드됨 | Skill 03 역공학 모드 강제 활성화. `clone_source_layout_idx` 채번 시작. 이 파일에서 레이아웃·컬러·폰트 DNA 추출 후 Section 2 리서치로 진입 |
| 브랜드 컬러 가이드 있음 | 추출된 제안사 브랜드 컬러를 Skill 02의 `dominant_bg` 또는 `accent_color` 기준으로 우선 반영. 고객사 CI는 보조 팔레트로 처리 |
| 레퍼런스 덱 업로드됨 | Skill 03 §2 LAYER 2 스토리라인 DNA 분석 추가 실행 후 Section 2로 진입 |
| 전부 없음 | 기본 디자인 시스템(Skill 12 default) + 고객사 CI 기반 60-30-10 팔레트로 진행 |

> **에러 방지 규칙:** 사용자가 아무런 파일도 제공하지 않았는데 에이전트가 임의 디자인으로 슬라이드를 생성한 경우, 이는 Pre-Flight Check 미실행으로 인한 파이프라인 위반이다. Skill 09 Phase 0 Audit에서 `[FAIL]` 처리하고 사용자에게 다시 확인한다.

## 1. 개요 (Overview)
본 사양은 에이전트가 파이프라인 시작 시([STATE: DISCOVERY]), Section 0 Pre-Flight Check 완료 후 사용자가 입력한 고객사명과 교육 주제를 바탕으로 '교육 주제 맞춤형 고객사 사전 리서치(Topic-Centric Pre-Search)'를 자동으로 실행하고, 이를 기반으로 고도로 구조화된 '교육제안 기획서(Proposal Planner)' 및 자가 진단 리포트를 수립하는 규칙을 정의한다.

---

## 2. 교육 주제 연동 자동 사전 리서치 규칙 (Pre-Search Query & Extraction)
사용자가 최초로 `[고객사명]`과 `[교육 주제]`를 입력하면, 에이전트는 질문을 던지기 전에 웹 검색 엔진(Web Search)을 가동하여 다음 3대 영역을 즉각 리서치해야 한다.

### ① 검색 쿼리 세트 자동 생성 및 실행 (Search Queries)
* 기본 비즈니스 행보 쿼리: `"{고객사명} {교육 주제} 도입"`, `"{고객사명} {교육 주제} 추진"`
* C-Level 메시지 및 비전 쿼리: `"{고객사명} 신년사 {교육 주제}"`, `"{고객사명} 대표 {교육 주제}"`
* 실무 조직 및 동향 쿼리: `"{고객사명} {교육 주제} 활용"`

### ② 핵심 인사이트 추출 (Insight Extraction)
검색된 뉴스 및 공식 문서 데이터에서 다음 3가지 핵심 팩트(Facts)를 추출하여 임시 컨텍스트 버퍼에 바인딩한다.

1. **[추진 동력]:** 고객사가 해당 주제(예: AI/AX)와 관련하여 최근 대외적으로 선포한 핵심 비전이나 전사 정책.
2. **[실행 단계]:** 자체 포털 구축, 외부 SaaS 도입, TF 조직 결성 등 현재 고객사가 도달한 기술적/실무적 실행 단계.
3. **[예상 허들]:** 망분리 보안 규제, 임직원의 디지털 격차, 실무 적용 유스케이스 부족 등 해당 기업이 겪고 있을 핵심 페인 포인트 추정치.

## 3. 리서치 기반 맞춤형 5대 역질문 프로토콜 (Tailored Questionnaire)
에이전트는 단순히 준비된 질문을 복사 붙여넣기 하지 않고, 앞서 자동 리서치된 인사이트를 질문 서두에 자연스럽게 녹여내어 전문성을 증명하며 질문해야 한다.

* ❌ **나쁜 질문 예시:** "수강생들의 직급과 AI 숙련도는 어떻게 되나요?"
* ⭕ **좋은 질문 예시 (리서치 연동형):**
  > "최근 S사가 전사 업무 효율화를 위해 '사내 자체 AI 포털'을 구축하고 업무 자동화를 가속화하고 있는 행보를 포착했습니다. 이번 교육을 듣는 대상 분들도 이 사내 포털이나 AI 도구를 현업에서 직접 활용해야 하는 실무진급 분들인가요? 그분들의 대략적인 현재 AI 숙련도 수준도 함께 알려주세요."

## 4. '교육제안 기획서' 표준 출력 서식 (Proposal Brief Template)
에이전트는 수집된 답변과 사전 리서치 데이터를 종합하여, 아래 구조의 명확한 '교육제안 기획서' 초안을 마크다운 형태로 렌더링한다.

```
# [교육제안 기획서] {고객사명} 대상 {교육과정명} 수립 안

## 1. 교육 개요 및 대상 정의
* **고객사명:** {고객사명}
* **희망 과정명 (추천):** {과정명}
* **교육 대상 및 규모:** {직무/직급}급 {인원수}명
* **현재 역량 레벨:** {초급 / 중급 / 고급}
* **교육 일정/기간:** 총 {N}일 (총 {H}시간)

## 2. 사전 리서치 및 제안 배경
* **고객사의 최신 행보 (★자동 분석):** {자동 사전 리서치로 파악된 해당 교육 주제 관련 기업의 최신 움직임 요약}
* **역량 Gap 및 Pain Point:** {고객사 행보 대비 임직원들이 겪는 실무상의 진짜 문제점}
* **교육 수립 방향:** {이 문제를 깔끔히 해결하기 위해 교육이 도달해야 할 최종 지향점}

## 3. 제안사 핵심 전략 매칭
* **제안사의 강점:** {선택된 제안사의 1순위 독보적 전문성}
* **유관 레퍼런스:** {매칭에 활용할 기존 대기업 유사 성공 이력}

## 4. 제안서 제작 전략 (Pitch Strategy)
* **피치 스타일:** {이론/체계 중심 보고용 (Heavy) / 실습/결과 중심 실전용 (Light) 중 선택 적용}
* **디자인 테마:** {고객사 브랜드 컬러 분석 연동 계획}
```

## 5. 기획서 완성도 및 타당성 자가 진단 (Planner Guardrails)
에이전트는 기획서를 출력하기 전, 아래 규칙에 의거하여 기획서의 현실성(Feasibility)을 진단하고, 의심스러운 부분이 있다면 기획서 하단에 [에이전트 권고 사항]을 주석으로 첨부한다.

1. **시간-난이도 미스매치 진단:**
   * **진단:** 교육 기간이 단기(1일, 8시간 이하)인데 요구 숙련도가 '고급'이거나 'AI 에이전트 직접 코딩 구축'과 같은 무거운 실무가 포함되어 있는가?
   * **에이전트 조치:** 기획서 하단에 "1일 특강성 과정으로는 실습 깊이에 한계가 있으므로, 핵심 개념 및 활용 시나리오 데모 위주로 커리큘럼을 전개할 것을 권장합니다"라고 조언 첨부.

2. **대상-피치 스타일 정합성 진단:**
   * **진단:** 교육 대상이 '실무 실무진 및 개발자'인데 피치 스타일이 '이론/체계 중심 보고용(Heavy)'으로 선택되었는가?
   * **에이전트 조치:** "현업 실무진 교육 제안이므로, 이론 장표는 최소화하고 '실습/결과 중심 실전용(Light)' 스타일로 빌드하여 실습 도구와 산출물을 강조할 것을 추천합니다."

## 6. 웹 검색 실패 시 Fallback 프로토콜 (Search Failure Fallback)

에이전트는 Section 2의 웹 검색이 실패하거나 결과가 불충분할 때, 아래 프로토콜을 순서대로 실행한다.

### Case 1: 검색 결과 0건 (Zero Results)
1. **1차 재시도:** 쿼리를 단순화하여 재검색 (`"{고객사명} AI"`, `"{고객사명} 디지털전환"`)
2. **2차 재시도:** 영문 쿼리로 전환 (`"{company_name} AI strategy"`, `"{company_name} digital transformation"`)
3. **수동 입력 요청 (Fallback):** 2회 재시도 모두 실패 시 사용자에게 아래 3항목 직접 입력 요청:
   - [추진 동력]: "현재 고객사의 AI/AX 관련 핵심 추진 방향이나 전사 정책을 알려주세요."
   - [실행 단계]: "현재 어느 단계에 있나요? (검토 중 / 파일럿 / 전사 도입 중)"
   - [예상 허들]: "가장 우려하는 현장 문제나 장벽이 무엇인가요?"
4. **최종 처리:** 사용자 입력값으로 기획서 진행. 리서치 출처 필드에 "사용자 직접 입력 (검색 불가)" 명시.

### Case 2: 검색 결과 관련성 낮음 (Low Relevance)
- 결과가 존재하지만 고객사 + 교육 주제와 직접 관련 없는 경우 (동명이인 기업, 전혀 다른 분야 뉴스 등)
- **조치:** 상위 3개 결과 관련성 판단 후 70% 미만이면 Case 1 Step 3으로 전환
- **부분 활용 허용:** 관련 있는 항목만 추출하고, 나머지는 "정보 부족 — 사용자 확인 필요"로 명시

### Case 3: 네트워크 에러 / API 타임아웃
- **자동 재시도:** 최대 2회, 지수 백오프 (5초 → 10초)
- **최종 실패 시:** 사용자에게 "⚠ 웹 검색 일시 불가 — 수동 입력 모드로 전환합니다" 안내 후 Case 1 Step 3으로 전환

## 7. [마스터 규칙] 강사 배제 표준 정의 (Master Instructor Exclusion Rule)

> **본 섹션은 전체 파이프라인의 단일 정의점(Single Source of Truth)이다.
> 스킬 03, 09, 11은 이 섹션을 참조하며 별도 재정의하지 않는다.**

### 배제 범위 (절대 포함 금지)
| 배제 항목 | 예시 |
|---|---|
| 강사 성명 | "김OO 강사", "홍길동 수석" |
| 강사 직함 / 이력 | "전 SKT AI 연구소장", "Microsoft MVP" |
| 강사 사진 / 프로필 이미지 | 인물 사진 포함 슬라이드 |
| 강사 소개 텍스트 블록 | "약력: ~에서 ~년간 재직" |

### 허용 범위 (배제 대상 아님)
| 허용 항목 | 이유 |
|---|---|
| 프로젝트명 + 고객사 + 만족도 평점 | 제안사 기관 실적이며 강사 개인정보 아님 |
| 교육 수행 연도 | 기관 단위 실적 데이터 |
| 교육 인원 규모 | 익명 집계 데이터 |

### 자가 검사 방법 (Claude-Verifiable)
생성된 JSON 내 모든 텍스트 필드에서 아래 패턴 탐지:
- **탐지 정규식:** `(강사|instructor|담당강사|수석|Lead|MVP|약력|경력 사항|프로필)`
- **탐지 시 조치:** 해당 필드를 프로젝트 실적 형식(`"프로젝트명 | 고객사 | 규모 | 만족도"`)으로 즉시 재작성 후 재검증

### 적용 시점 (각 스킬 연동)
- **Skill 03 Section 3 Rule 1:** 레거시 템플릿에서 강사 프로필 레이아웃 복제 금지
- **Skill 09 Phase 1 Audit:** JSON 내 강사 관련 텍스트 정규식 스캔 → `instructor_excluded: true` 플래그 설정
- **Skill 11 Phase 1 Flow:** 위 스캔 결과를 Integrity Pass 보고서에 반영
