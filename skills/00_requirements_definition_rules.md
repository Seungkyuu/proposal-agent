# Agent Skill 00: Requirements Definition & Pre-Flight (Phase 0)

## 0. 개요

**본 스킬은 파이프라인 최초 진입점이다.**
에이전트가 고객사명과 교육 주제를 입력받으면, 기획·디자인·렌더링 작업을 시작하기 전에 반드시 이 스킬을 먼저 실행한다.

**목적:**
사용자로부터 제안서 생성에 필요한 모든 정보를 구조화된 질문으로 수집하고, "요구사항 정의서"를 작성하여 사용자의 승인을 받는다. 승인 전까지 Phase 1(기획안)은 절대 시작하지 않는다.

**실행 순서:**
```
Skill 00 (Phase 0) → 사용자 승인 → Skill 01~07 (Phase 1~3) → 사용자 승인 → 03_content.md 전달
```

## 1. 질문 수집 프로토콜

에이전트는 아래 5개 블록을 순서대로 질문한다.
한 번에 전체를 묻되, 사용자가 모르는 항목은 "모름" 또는 "미정"으로 답할 수 있음을 안내한다.

### 에이전트 발화 템플릿

```
[고객사명] 제안서 작업을 시작하겠습니다.
기획안을 제대로 작성하기 위해 먼저 아래 항목들을 확인하겠습니다.
모르시는 항목은 '미정' 또는 '없음'으로 답해 주시면 됩니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
① 고객사 기본 정보
  1-1. 고객사명 / 업종 / 규모 (직원 수 또는 계열사 수)
  1-2. 교육 의사결정자 직급·성함 (공개 가능 범위 내)
  1-3. 최근 AI·DX 관련 공개 선언이나 전사 정책이 있다면 알려주세요.

② 교육 요구사항
  2-1. 교육 주제 및 과목 수 (예: AI 활용 3개 과목)
  2-2. 교육 대상: 직급, 인원 수, 현재 AI 활용 수준 (초급/중급/고급)
  2-3. 총 교육 시간 및 일정 (예: 총 24시간, 3일 집합)
  2-4. 교육 형태: 집합 / 온라인 / 혼합
  2-5. 교육장 인터넷 환경: 자유롭게 사용 가능 / 망분리로 외부 접속 불가 / 미확인
       (공공기관·금융기관은 반드시 확인 — 결과에 따라 실습 도구 전체가 바뀜)
  2-6. 실습 PC 환경: 수강생 개인 노트북 지참 / 기관 PC 제공 / 미정
  2-7. 고객사 주요 업무 목록
       (예: 어떤 공문서를 주로 작성하는지, 민원 유형, 보유 데이터 현황 등
        실습 소재를 고객사 실무에 맞추기 위해 사용)

③ 제안서 조건
  3-1. 제출 기한
  3-2. 단독 제안 여부 (경쟁 입찰인지 단독인지)
  3-3. 특별히 강조하고 싶은 포인트 (있다면)
  3-4. 절대 포함하면 안 되는 내용 (있다면)
  3-5. KPI·사후관리 납품 범위
       (교육 종료 후 실제로 제공 가능한 범위를 사전 확정
        예: 만족도 조사만 / 4주 리마인더 발송 / 6개월 ROI 추적
        → 확정된 범위만 제안서에 기재. 실행 불가능한 내용 기재 금지)

④ 알파코 자산 확인
  4-1. 이번 제안서에 활용 가능한 실제 레퍼런스 고객사명
       (공개 불가라면 업종+규모로 익명 처리 가능 여부)
  4-2. 별도 브랜드 컬러 가이드 또는 로고 파일 있으면 공유해 주세요.

⑤ 산출물 스펙
  5-1. 희망 슬라이드 분량 (예: 18~20장)
  5-2. 섹션 구분 슬라이드 포함 여부
  5-3. 견적·가격 슬라이드 포함 여부
  5-4. 교육 일정표 슬라이드 포함 여부
       ※ 알파코 회사 소개 슬라이드는 기존 제안서 소스 덱에서 항상 제공되므로 별도 확인 불필요.
          Phase 2 레이아웃 설계 시 자동 포함 처리.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 3. 미확인 항목 기본값 (Default Assumption)

사용자가 답변하지 않은 항목은 아래 기본값을 적용하되, 요구사항 정의서의 "미확인 항목" 섹션에 반드시 명시한다.

| 항목 | 기본값 |
|---|---|
| 슬라이드 분량 | 18장 |
| 섹션 구분 슬라이드 | 포함 |
| 견적 슬라이드 | 미포함 (별도 확인 필요) |
| 교육 일정표 | 포함 |
| 알파코 회사 소개 슬라이드 | 항상 포함 (소스 덱에서 자동 제공) |
| AI 수준 | 초급 가정 |
| 교육 형태 | 집합 |
| 인터넷 환경 | 미확인 → Phase 1에서 반드시 확인 후 도구 선정 |
| PC 환경 | 미정 → 개인 노트북 지참 가정 |
| KPI 납품 범위 | 만족도 조사(Level 1)만 기본 제공. Level 2~4는 별도 확인 필요 |
| 브랜드 컬러 | 고객사 CI 기반 자동 추출 (Skill 02 적용) |
| 레퍼런스 공개 범위 | 업종+규모 익명 처리 |

## 4. 승인 전 진행 금지 규칙

다음 행동은 사용자가 요구사항 정의서를 **명시적으로 승인하기 전까지** 절대 수행하지 않는다.

| 금지 행동 |
|---|
| 기획안(Phase 1) 초안 작성 |
| 웹 리서치 실행 |
| 커리큘럼 설계 |
| 슬라이드 수 임의 결정 |

> **위반 감지 시:** Skill 09 Phase 0 Audit에서 `[FAIL]` 처리하고 Skill 00으로 되돌아간다.

---

## 5. 수정 요청 처리 규칙

사용자가 요구사항 정의서의 일부를 수정 요청하면:

1. 해당 항목만 수정하고 정의서 전체를 재출력한다.
2. 버전을 v1.1, v1.2 순으로 올린다.
3. 수정된 항목 옆에 `[수정됨]` 태그를 붙인다.
4. 재승인을 요청한다.
