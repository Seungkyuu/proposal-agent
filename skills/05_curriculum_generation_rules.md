# Agent Skill: Curriculum Generation & Module Architecture Rules

## 1. 개요 (Overview)
본 사양은 에이전트가 Step 5(제안 커리큘럼) 단계를 수행할 때, 뻔하고 추상적인 목차 생성을 방지하고 [교육 대상의 직무/직급]과 [고객사 도메인의 실제 업무 시나리오]가 결합된 초밀착형 커리큘럼 및 세부 차시 데이터를 동적으로 엔지니어링하는 규칙을 정의한다.

---

## 2. 커리큘럼 설계의 5단계 레이아웃 매트릭스 (Curriculum Matrix)

에이전트가 생성하는 모든 커리큘럼 모듈은 단순한 주제 나열이 아닌, 반드시 아래 5대 필수 요소(Matrix)가 상호 연동된 구조로 명세화되어야 한다.

| 차시 (Time/Session) | 세부 주제 (Topic) | 핵심 학습 내용 (Core Concept) | 실습 및 액티비티 (Hands-on/Tool) | 최종 실습 산출물 (Artifact) |
| :---: | :--- | :--- | :--- | :--- |
| **시간/일차** | 구체적인 핵심 학습 타이틀 | 다루는 핵심 개념 및 이론 | 실제 탑재할 실습 환경 및 프롬프트 템플릿, AI 도구 | 수강생이 이 세션을 마쳤을 때 손에 쥐는 실물 결과물 |

* **❌ 가짜 실습 예시:** "AI 프롬프트 실습 진행" (산출물이 명확하지 않음)
* **⭕ 진짜 실습 예시:** "Claude Code 연동 실무 자동화 툴 빌드 실습" ➔ [산출물: 사내 DB 연동형 FAQ 자동 생성 챗봇 프로토타입]

### 커리큘럼 표 출력 포맷 (01_strategy.md 및 03_content.md)

커리큘럼 행렬은 반드시 아래 **고정 5열 헤더**의 마크다운 표로 출력한다. 헤더 명칭 임의 변경 금지.

```markdown

|------|---------|-------------|-------------------|-----------|
| 1차시 (09:00~10:30) | AI 현황 및 프롬프팅 기초 | LLM 동작 원리, 프롬프트 구조 설계 | Claude.ai 실습 환경 접속 및 기초 프롬프트 작성 | 부서별 업무 유형 맞춤 프롬프트 템플릿 3종 |
```

## 3. 대상(Target Audience)별 커리큘럼 튜닝 규칙 (Audience Tuning)

에이전트는 Step 1(기획서 작성)에서 확보된 교육 대상의 속성에 따라 실습 도구와 이론 비율, 최종 결과물의 성격을 완벽하게 다이어트해야 한다.

### ① C-Level 및 임원진 (Executive Level)
* **이론 대 실습 비율:** [이론/전략 80% : 실습/체험 20%]
* **커리큘럼 초점:** 글로벌 기업의 비즈니스 AX 도입 성공/실패 케이스 스터디, AI 거버넌스 및 보안 리스크 관리, AI 기반 비즈니스 기획 방법론.
* **실습 내용:** 코딩 없는 아주 직관적인 AI 툴 체험 (예: 웹 브라우저 기반 LLM 활용 경영 데이터 요약).

### ② 중간 관리자 및 팀장급 (Manager Level)
* **이론 대 실습 비율:** [전략/워크플로우 50% : 실습 50%]
* **커리큘럼 초점:** 팀원들의 AI 업무 활용 장려법, 부서 전용 프롬프트 템플릿 관리 가이드, AI 활용을 통한 팀 리소스 절감액 관리 및 모니터링 기법.
* **실습 내용:** 부서별 맞춤형 커스텀 GPTs/프로젝트(Project) 공간 설계 워크숍.

### ③ 현업 실무진 및 개발자 (Working Professional / Developer)
* **이론 대 실습 비율:** [이론 10% : 실습 90%]
* **커리큘럼 초점:** 실제 업무 도메인 100% 매핑 실습, 자동화 툴(Zapier, Make 등) 또는 Claude Code를 이용한 무인 워크플로우 파이프라인 구축. API 키 기반 도구(Claude API 등)는 `metadata.json`의 도구 체계에 명시된 경우에 한해 포함한다.
* **실습 내용:** API 키 발급부터 실제 자동화 챗봇 개발, 사내 문서 전용 검색(RAG) 엔진 테스트 등.

## 4. 도메인(산업군) 맞춤형 실습 시나리오 주입 (Domain Alignment)

에이전트는 Step 2(제안 배경 기획)에서 도출된 고객사의 실제 업종별 데이터와 시나리오를 세부 차시 실습 내용에 강제 바인딩한다.

* **[금융/보험 도메인]:** 여신 심사 보고서 자동 요약 실습, 약관 대조 비교 자동화 봇 제작, 금융 리포트 차트 데이터 추출 실습.
* **[제조/물류 도메인]:** SCM 공급망 예측 리포트 자동 작성, 설비 오류 로그 데이터 패턴 분석, 납품 처리를 위한 문서 자동 분류 봇 빌드.
* **[마케팅/커머스 도메인]:** 소셜 미디어 트렌드 분석 카피라이팅, 페르소나별 상세 페이지 문구 대량 생성 자동화, 고객 리뷰 감정 분석 파이프라인 실습.
* **[공공/정부 도메인]:** 행정 공문서(품의서·보도자료·회의록) AI 초안 작성 실습, 민원 FAQ 구조화 및 Custom GPT 챗봇 구현, 공단 운영 데이터 시각화 대시보드 실습.

## 4-1. 망분리 환경 대응 실습 도구 선택 규칙

Skill 00 요구사항 정의서의 **2-5 인터넷 환경** 값에 따라 실습 도구를 반드시 아래 기준으로 선택한다.

| 인터넷 환경 | 사용 가능 도구 | 대체 도구 |
|---|---|---|
| 자유롭게 사용 가능 | Claude.ai, ChatGPT Plus, Custom GPTs, Canva AI, Vrew 등 클라우드 기반 전체 | — |
| 망분리로 외부 접속 불가 | MS Office 내장 Copilot (사내 허가 시), 로컬 설치형 도구 | 클라우드 SaaS 전면 사용 불가. 커리큘럼 전면 재설계 필요 |
| 미확인 | 클라우드 도구로 기획하되, 제안서에 "교육장 인터넷 환경 사전 확인 필요" 주석 삽입 | — |

> **위반 금지:** 망분리 환경이 확인되었는데 Claude.ai, ChatGPT Plus 등 외부 접속 필수 도구를 커리큘럼에 포함하면 `[FAIL]` 처리.

## 5. 교수설계 모델(Instructional Design)과의 일관성 검증 (Self-Consistency)

에이전트는 Step 4에서 선택한 교수설계 모델의 교수법 패턴이 커리큘럼에 고스란히 반영되어 있는지 자가 검증(Cross-Check)한다.

* **[PBL(문제해결) 선택 시]:** 커리큘럼의 최소 30% 이상(보통 1일차 오후 또는 2일차 전체)이 "현업 문제 해결을 위한 조별 해커톤(Hackathon) 및 전문가 1:1 밀착 피드백, 그리고 최종 데모 발표" 세션으로 단독 배정되어 있는지 체크한다.
* **[역방향 설계(Backward) 선택 시]:** 1차시 초입에 수강생의 현재 역량 측정 및 도출해야 할 최종 결과물의 정확한 스펙(Spec) 합의 프로세스가 있고, 마지막 차시에 이를 직접
