# Agent Skill: Reference Deck Tone & DNA Extraction Rules (V5. Content-Only)

## 1. 개요 (Overview)

본 사양은 에이전트가 기존 알파코 레퍼런스 제안서(PPTX, PDF, 이미지 등)를 참고할 때,
해당 문서의 **비주얼 DNA(Visual DNA)**와 **스토리 톤(Story Tone)**을 분석하여
새로운 제안서의 **카피라이팅 스타일과 문장 구조**에 일관되게 반영하기 위한 규칙을 정의한다.

강사진 프로필 레이아웃은 전면 배제한다.

> **역할 범위 (V5 변경):** 이 Skill은 텍스트 콘텐츠와 톤앤매너 추출에만 집중한다.
> python-pptx 렌더러 연동, shape 인덱스 매핑, JSON Bridge 기능은 Phase 4 제거에 따라 폐기되었다.

## 2. 레퍼런스 덱 3대 분석 레이어 (Deconstruction Layers)

에이전트는 제공받은 기존 문서를 다음 3가지 축으로 분석하여 컨텍스트에 바인딩한다.

```
[레거시 파일 입력 (PPTX / PDF / 이미지)]
│
├── LAYER 1: 비주얼 스타일 감지 (참고 전용)
│     - 도미넌트/서브/액센트 컬러 세트 파악 (Skill 02로 전달)
│     - 텍스트 정렬 기준, 여백 비율, 라인 데코 양식 감지
│     - 슬라이드별 정보 밀도(텍스트 vs 여백 비율) 파악
│
├── LAYER 2: 스토리라인 전개 흐름 분석
│     - 제안 논리의 빌드업 방식 (두괄식 결과 우선형 vs 귀납적 문제제기형)
│     - 섹션 구분 슬라이드(Section Divider) 사용 주기
│     - 각 섹션 내 슬라이드 구성 패턴 (문제→해결→증거 순서 등)
│
└── LAYER 3: 문장 톤앤매너 추출 (Skill 07·15에 반영)
      - 사용 어휘의 전문성 수준 (학술 용어 vs 실무 직관 용어)
      - 불릿 포인트 문장 구조 및 어미 패턴
      - 명사형 종결 여부, 대구법 사용 빈도
```

## 3. 톤앤매너 이식 규칙 (Reconstruction Rules)

추출된 DNA를 기반으로 새 제안서의 카피라이팅을 작성할 때 아래 규칙을 적용한다.

### 규칙 1: 문장 밀도 보존
- 원본 문서의 슬라이드당 평균 글자 수를 파악한다.
- 새 슬라이드 작성 시 원본 글자 수의 **±15% 한계선**을 넘지 않도록 텍스트 분량을 조절한다.
- 원본이 여백 중심(저밀도)이면 새 제안서도 저밀도로 유지한다.

### 규칙 2: 어미·문장 구조 일치
- 원본이 개조식 명사형 종결이면 새 제안서도 100% 명사형으로 통일한다.
- 원본이 대구법(`~을 통한 ~의 실현`) 구조를 반복하면, 새 슬라이드의 불릿 헤더도 동일한 리듬감으로 작성한다.

### 규칙 3: 강사 프로필 레이아웃 복제 금지
- 레퍼런스 덱에 강사 이름·약력·이력이 포함된 슬라이드가 있어도 해당 레이아웃과 내용을 복제하지 않는다.
- 상세 기준은 **Skill 01 §7 (강사 배제 표준 정의)** 참조.

## 4. 분석 결과 활용 범위

| 활용처 | 내용 |
|---|---|
| Skill 02 (색상) | LAYER 1에서 파악한 브랜드 컬러를 Skill 02 컬러 파이프라인에 전달 |
| Skill 07 (카피라이팅) | LAYER 3 톤앤매너 → 카피라이팅 스타일 가이드로 반영 |
| Skill 15 (콘텐츠 출력) | LAYER 2 스토리라인 흐름 → 슬라이드 순서·메시지 위계에 반영 |
| Skill 08 (구조) | LAYER 2 섹션 구성 패턴 → Phase 2 슬라이드 구조 설계에 반영 |

## 5. 레퍼런스 파일 분석 실패 시 Fallback

| 상황 | 처리 |
|---|---|
| 이미지 PDF (OCR 불가) | 톤앤매너는 알파코 기본 스타일(명사형·저밀도) 적용. 컬러는 사용자에게 직접 확인 요청 |
| 파일 미제공 | 기존 알파코 제안서 기본 DNA(결과 우선형, 명사형, 저밀도) 기본값 적용 |
| 분석 항목 부분 실패 | 성공한 레이어 결과만 반영, 실패 항목은 기본값 사용. 사용자에게 알림 |
